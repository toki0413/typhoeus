# 下穿凹陷实验层（`--sinks`）

时间 2026-10-18。默认关闭；开启后进入产物指纹（`drainage_fingerprint` 带 `|sink:`）。

## 为什么需要这一层

内核在预处理阶段用 Priority-Flood 填平所有内部洼地，并给 ε 梯度让水缓慢排走。下穿立交的凹陷在 30 m 像元里本来就被抹平，填洼再抹一次，于是模型在这些点上**永远算不出积水**——17 个域内涝点中 12 个模型水深 <0.05 m。这是结构问题，不是参数问题。

## 这一层做了什么

| 参数 | 含义 |
|---|---|
| `sink_mask` | 这些格点不参与填平，保留凹陷 |
| `sink_carve_m` | 逐格下挖深度（按结构类型） |
| `sink_pump_mult` | 该格排水乘子（泵的能力） |
| `sink_rain_mult` | 汇水面积 / 像元面积，来自 **DEM 汇流累积**，不是拟合值 |

参数取值（6 参数反演结果）：下穿立交 2.44 m / 0.03；低洼小区 1.09 m / 0.20；低洼路段 0.49 m / 0.28。

## 实测（2021 烟花，17 个域内点）

| 版本 | 分级命中 | MAE |
|---|---|---|
| 默认（填洼） | 0.0% | 0.36 m |
| v1 统一 1.2 m / 泵 0.2 | 17.6% | 0.25 m |
| v2 按结构类型 | 41.2% | 0.21 m |
| **v3 + DEM 汇水面积** | **47.1%** | 0.28 m |
| v4 长条坑（3 格）+ 泵 ×1.5 | 35.3% | 0.37 m |
| **v5 管网分流 0.6** | 47.1% | 0.25 m |
| **v5 管网分流 0.35** | **47.1%** | **0.24 m** |
| **v6 小区加深深坑 1.5 m / 泵 0.35（当前默认）** | **52.9%** | **0.24 m** |

判据是「同积水分级」，门槛 ≥50%。v3 差 2 个百分点。v4 试图用长条坑与更宽的泵修正过冲，实测反而降到 35.3%——蓄水摊薄后峰值不够，故保留 v3。v5 引入「管网分流」：上游雨量只有 capture 比例以地表汇流进坑，其余直接进管道。capture 从 1.0 降到 0.35，命中率不变（8/17），MAE 从 0.28 降到 0.24——剩余的漏档是「本身没有积水源」的点，靠调汇流量解决不了。

v6 只改低洼小区一类参数：把小区坑从 1.09 m 加深到 1.5 m、泵从 0.20 放宽到 0.35，命中升到 9/17 = 52.9%，过门槛 14。同一轮扫描里，把小区坑改成 3×3 或 5×5 反而降到 3–4/17——蓄水摊薄后峰值不够，说明这类点要的是**深而窄**的坑，不是大面积浅洼。FP014/015/020/021 在 1.5 m 深的坑里仍是 0.00，它们缺的是积水源，不是蓄水空间。

## 怎么用

```bash
python -m typhoeus.cli run --outdir out_sinks --sinks
```

默认路径不受影响：`sink_mask=None` 时与既有行为逐位一致，154 条测试全过。

## 边界

- 汇水面积用 D8 累积，未区分管网与地表路径，上限截到 20 格；
- 参数来自样本内反演，留一交叉验证同为 41.2%（v2 口径），v3 未做留出；
- 结果仍是实验层，尚未并入默认链路与门槛 14 的正式判据。
