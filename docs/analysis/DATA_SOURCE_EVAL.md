# 数据接口评估与选型

编制时间 2026-10-15。本文档回答四个方向（气象、天文历算星历、地理坐标、天文观测）的数据源可用性，并对每源给出覆盖范围、精度、授权与配额、密钥要求、接口形式，最后按可用性排序给出选型结论。所有标注"实测"的数字来自本轮在本机发出的真实请求，响应体与耗时均已核对。

---

## 一、中科天机数据接口评估

### 1.1 定位纠正

中科天机（www.tjweather.com）不是天文历算服务，是**气象数值模拟公司**。其技术底座是自研 SD3 引擎：有限体（FV）平流方案、球立方变网格、全球 12 km / 中国区域 3 km、逐小时 160+ 要素。把它归入"天文历算"方向是误配；它在本项目中属**气象方向**的国内商业候选。

### 1.2 接口规格（官网 API 文档核实）

| 项 | 值 |
|---|---|
| 申请入口 | `https://www.tjweather.com/Apply` 或 `/Service` 页申请 API 服务 |
| 认证 | 基于 key 的用户认证，调用其他所有接口须携带 APIKey |
| 协议 | 仅 HTTPS |
| 返回 | JSON，`Content-Type: application/json; charset=UTF-8`，UTF-8 |
| 成功格式 | `{"code":200,"message":"成功","data":对象或列表}` |
| 错误格式 | `{"code":非200,"message":"xxx","data":""}` |
| 首批要素 | 地面 6 要素：t2m、ws10m、wd10m、slp、rh2m、tp |
| 可选要素 | 100 m 风速风向、辐照度、总云量、低云量等单点数据 |
| 文件与流 | 文件下载与流请求返回数据流 |
| 免费试用 | **非商业用户首次免费 2 个月**；历史预报 API 试用为 1 个月 + 赠送 1000 次访问量 + 5 次/秒 |

### 1.3 结论：可用，但不能作为赛事期主力数据源

三条硬约束：

**配额量级不匹配。** 历史预报 API 赠送 1000 次访问量。本项目 17 个涝点 × 多场事件 × 逐小时，单场事件若取 3×3 网格 9 点 × 72 小时即 9 次调用，1000 次只够百场量级的点查询，且这是赠送额度不是持续额度。正式商用需走「按量计费」，报价未公开，需商务接触。

**免费试用明确排除商业用途。** 文档原文"非商业用途用户首次可免费试用 2 个月，若需……开展商业合作，可通过平台首页【客服咨询】联系我们"。赛事演示属非商业，可正当使用；但产品化路径必须付费。

**要素与时距匹配尚可但非最优。** 其降水（tp）为模式输出，不是实测。对本项目 −46% 偏差这个核心问题，模式预报数据不能当"实测降雨"用，只能作旁证。

### 1.4 一条值得单独记的发现

中科天机已加入 **Amazon Open Data** 计划，其数据集以标准 NetCDF + S3 架构向全球免费开放，含东南亚与非洲 0.1° 逐小时预报场、台风路径等百余种变量，无需注册 AWS 账号。**但覆盖范围是东南亚与非洲，不含中国**，对本项目无直接价值。若未来要评估"中国区域公里级数据"（中科天机 2025-09 与怀柔科学城签约后承诺逐步开放），需重新查证，本轮无公开证据支持已开放。

## 二、气象方向（与本项目瓶颈直接相关）

### 2.1 实测：Open-Meteo 的历史端点无 key 可用，且能显著改善 −46% 偏差

搜索结果声称"Historical / Climate / Ensemble / Satellite Radiation API 需 Professional 或更高付费档"。**实测推翻了这一条**：

```
archive-api.open-meteo.com/v1/archive?latitude=29.87&longitude=121.56
  &start_date=2021-07-24&end_date=2021-07-27&hourly=precipitation&timezone=Asia/Shanghai
→ HTTP 200，返回逐时降水序列（无 API key、无账号）
```

对比同一服务，`/v1/ecmwf-hres`（Single Runs）返回 HTTP 404 Not Found，`/v1/forecast` 拒绝 2021 年日期（`Parameter 'start_date' is out of allowed range from 2026-07-14 to 2026-10-30`）。即：**forecast 与 single-run 需付费档，archive（ERA5 再分析）无 key 可用**。

**实测复算 2021 烟花台风（2021-07-24 至 07-27）宁波降雨：**

| 位置 | 坐标 | ERA5 逐时累计 | 官方实测 | 相对误差 |
|---|---|---|---|---|
| 宁波站 | 29.87 N / 121.56 E | 218.3 mm | — | — |
| **余姚** | 29.99 N / 121.15 E | **405.1 mm** | **475 mm** | **−14.8%** |
| 宁海 | 29.29 N / 121.43 E | 184.3 mm | — | — |
| 域内 3×3 粗网格面平均 | — | **286.3 mm** | **全市面雨量 375 mm** | **−23.7%** |
| **当前产品内核** | — | **202.5 mm** | **375 mm** | **−46.0%** |

3×3 网格九点实测值（mm）：

```
lat=29.7:  447.0  246.2  206.2
lat=29.9:  451.8  258.4  213.9
lat=30.1:  280.8  280.2  192.3
```

**这组数字改变了对 −46% 的判断。** 三点：

1. 输入源本身贡献约一半偏差。同一场事件，ERA5 面平均 −23.7%，内核 −46.0%，两者之差 22.3 个百分点属于内核自身的处理问题（时距分配、面雨量口径、或降雨落区偏移）。此前把 −46% 整体归给"输入不可信"是不准确的。
2. 暴雨中心位置被复现。ERA5 最大值落在西南象限（余姚、奉化一带 447–452 mm），与官方"余姚 475 mm、单站丁家畈 1048 mm"的暴雨中心一致；当前内核把降雨铺得过于均匀。
3. 门槛 15（降雨总量相对误差 ≤15%）用 ERA5 仍不达标（−23.7%），但已从 BLOCKED 推进到可量化改进。**这不构成解锁**，只把差距从 2.3 倍压到 1.6 倍。

### 2.2 CMFD v2.0：仍是解锁门槛 14/15 的唯一正解

| 项 | 值 |
|---|---|
| 数据集 | 中国区域地面气象要素驱动数据集 v2.0（CMFD 2.0） |
| 托管方 | 国家青藏高原科学数据中心（`data.tpdc.ac.cn`） |
| DOI | 10.11888/AtmosphericPhysics.tpe.249369.file |
| 时空范围 | 1951-01-01 — 2024-12-31（74 年） |
| 时距 / 空间 | 3 小时 / 0.1°（约 10 km），陆地区域 70–140°E、15–55°N |
| 体积 | 1.03 TB |
| 要素 | t2m、slp、q（比湿）、风速、向下短波/长波辐射、降水率；派生量含近地面相对湿度、雨雪分离降水 |
| 共享方式 | **开放获取，填写数据用途说明后可直接下载** |
| 技术来源 | ERA5 再分析 + 气象站观测融合；辐射与降水产品集成 ISCCP-ITP-CNN 与 TPHiPr（AI 技术产品） |
| 文件命名 | `VVVVV_CMFD_Vvvvvv_CCCC_ttttt_sssdeg_YYYYYMM.nc`，例 `temp_CMFD_V0200_B-01_03hr_010deg_197901.nc` |
| 压缩方式 | 2.0 放弃 1.6 的 scale_factor/add_offset 整数化，直接 NetCDF4 存浮点 |

**两个此前未确认的接入障碍**：

- **账号**：需中国科技云通行证，实测反馈约 5 分钟注册，建议用机构邮箱（个人 QQ 邮箱有时收不到验证码）。
- **交付方式**：FTP（`ftp.tpdc.ac.cn:21`，目录 `/CMFD_V2.0/年份/`），非 HTTP API。申请后邮件下发 FTP 账号。有实测反馈称当天可收到含账号的邮件，填详细研究用途可加快。

**1.03 TB 对本项目是否必要**：不需要。只取 2021 年、宁波域（`120.8–122.2°E`、`28.8–30.4°N`）的降水率文件，单变量单年约在 10–20 MB 量级。这解决了"1 TB 太大下不动"的顾虑。

**CMFD 相对 ERA5 的增量价值**：融合了气象站观测，在青藏高原等复杂地形精度提升明显；辐射与降水产品本身就是 AI 神经网络生成。对本项目 −23.7% 这一层，CMFD 是唯一有希望压到 15% 以内的输入。

### 2.3 其余气象源

| 源 | 覆盖 | 精度 | 配额 | 密钥 | 接口 | 实测 |
|---|---|---|---|---|---|---|
| **MET Norway Locationforecast 2.0** | 全球逐小时，9 天 | ECMWF 骨干，前 48 h 强 | 20 req/s，须守 `Expires` 头 | 无（**强制 User-Agent 含联系方式**） | HTTPS GET + GeoJSON | **HTTP 200 / 3.56 s** |
| **彩云天气** | 中国大陆任意经纬度 | 多源融合 | 500 次/日，10 req/s | 需 token | REST JSON | 未测 |
| **和风天气** | 全球 + 格点 3–5 km | 中国精度高 | 免费订阅 **5 万次/月**；另有 1000 次/日口径 | 需 key（支持 JWT+EdDSA） | REST JSON | 未测 |
| **中央气象台台风网** | 西北太平洋/南海 | 官方 | 无公开 API，网页爬取 | 无 | HTML 爬取 | 未测 |
| **IMERG V07** | 全球 | 30 min / 0.1° | Earthdata 注册 | 需 Earthdata 账号 | HTTPS | 未测 |

MET Norway 的三点注意事项：2020 年起的新服务对**缺失或泛化 User-Agent 直接 403 封禁**（不是限流）；坐标只接受 4 位小数；80°N 以上精度明显下降。响应结构嵌套深（`properties.timeseries[].data.instant.details`），接入需留解析时间。

中央气象台台风网没有公开 API，网页结构可爬，适合小批量补台路径，不适合稳定管线。

IMERG 存在已知物理局限：卫星反演对台风眼墙强降水系统性低估，对本项目要解决的强降雨量级问题是反向的。

### 2.4 MCP 服务生态：气象类已有多个可用实现

| 实现 | 语言 | 底层数据 | 密钥 | 说明 |
|---|---|---|---|---|
| **`@lakphy-tools/caiyun-mcp`** | TypeScript | 彩云天气 | 需 `CAIYUN_API_TOKEN` | 6 个工具，含**分钟级降水**（未来 120 min 逐分钟，基于雷达回波）、县级官方预警。npm 发布 |
| **`hefeng-qweather-mcp`** | Python | 和风天气 | key 或 JWT+EdDSA 双认证 | `uv tool install` 或 pip 装。含**台风列表/实况路径/预报路径**（西北太平洋）、格点天气（3–5 km）、历史数据、空气质量、生活指数 16 种 |
| **`mcp-weather`** | Rust | Open-Meteo + Nominatim | **无** | streamable HTTP，4 个只读工具。Docker 镜像 `atareao/mcp-weather` |
| **Open-Meteo MCP** | TypeScript | Open-Meteo 全家 | 无（免费层） | 需 Node ≥22。覆盖 forecast / ERA5 archive / 空气质量 / 海洋 / GloFAS 洪水 / CMIP6 气候投影 / 集合预报。MIT |

**对本项目的判断**：MCP 层的价值不在"接数据"，在于**把六个 JSON 编译输出暴露成 Agent 可调的工具**——`RND.render_dashboard` 与六份编译输出的读取逻辑已成型，包一个 MCP server 即可让 Agent 直接问"余姚这批涝点的恢复次序是什么"。这是路线图第四章的自动化入口，不是数据管线的替代。

气象类 MCP 都不解决本项目的核心卡点：它们给的是**预报**，而门槛 15 要的是**实测/再分析**。`mcp-weather` 的无密钥特性让它适合做演示环境的降级源。

## 三、天文历算星历方向

**这一方向与本项目无耦合关系。** 台风—暴雨—内涝复合风险不含任何天文历算量（太阳位置、月相、潮汐均不进入内核）。列出规格备查，不作选型。

| 源 | 覆盖 | 精度 | 配额 | 密钥 | 接口 |
|---|---|---|---|---|---|
| **JPL Horizons** | 150 万+ 天体，9999 BC — 9999 AD，任意观测点 | 专业天文台级 | 无公布上限；要求一次请求长时间跨度而非循环单历元 | **无**，NASA 政府作品不受版权 | `ssd.jpl.nasa.gov/api/horizons.api`，`format=json` |
| **Skyfield**（Python 库） | 行星/恒星/卫星（TLE） | 与 USNO 天文年历一致，误差 **< 0.0005 角秒**（半毫角秒）；对 JPL 官方数据对齐 | 无配额概念，本地计算 | 无 | 库，`pip install skyfield`，唯一二进制依赖 NumPy，MIT |
| **JPL SBDB** | 全部已知小行星与彗星轨道 + 物理参数 | MPC 最新观测 + 雷达测距 | **Fair Use Policy：一次只发一个请求，不得并发**；须应用专用 User-Agent 含产品名/版本/联系方式 | 无 | `ssd-api.jpl.nasa.gov/sbdb.api`，v1.3 |
| **USNO / NAIF SPICE** | 本地星历内核 | 最高 | 无（本地） | 无 | C/C++ 库 + Python 封装 |

Horizons 的接口形状是历史包袱：参数须用单引号并 URL 编码为 `%27`，缺引号会静默误解析；返回是 JSON 里包一个定宽文本大块（`result` 字段），须按 `$$SOE`/`$$EOE` 切分。要接就装 Skyfield，别手写 Horizons 解析。

若将来确有星历需求（例如引入太阳辐射做蒸散项），Skyfield 是唯一正确选择——纯 Python、无编译、MIT、亚角秒级。

## 四、地理坐标方向

| 源 | 覆盖 | 配额 | 密钥 | 坐标系 | 实测 |
|---|---|---|---|---|---|
| **Nominatim**（公共实例） | 全球正/逆地理编码 | **绝对上限 1 req/s**；长跑脚本 **4 req/min**；单线程单机；结果必须缓存 | 无（须有效 Referer 或应用专用 User-Agent，HTTP 库默认 UA 不算） | WGS-84 | **HTTP 000，10.3 s 超时** |
| **天地图** | 地名搜索 V2.0、地理编码、逆地理编码、行政区划、静态地图 | 个人开发者：地理编码/逆地理编码各 **7000 次/日**，地图瓦片 10000 次/日，静态地图/行政区划/搜索/路径规划各 3000 次/日；企业 600 万次/日；政府 800 万次/日 | 需 key | **CGCS2000** | 未测 |
| **高德 Web 服务** | 2 亿 POI，200+ 国家 | 普通开发者 6000 次/日；认证个人 **30 万次/日**；认证企业 300 万次/日。QPS 100/200/1000 | 需 key + 企业实名认证 | **GCJ-02** | 未测 |
| **百度地图** | — | 企业 2000–15000 次/日（按接口不同） | 需 key + 企业认证 | **BD-09** | 未测 |

**Nominatim 实测不可用。** 10.3 s 超时返回 000，与本项目此前对 OSM Overpass 的实测结论（406/500/000）一致——公共 OSM 基础设施在中国大陆网络环境下不可依赖。其政策还明确禁止客户端自动补全、禁止网格系统查询、禁止批量下载区域全部 POI，自建实例需 64 GB RAM + 1.5 TB SSD 并导入 1–3 天，对本项目收益为零。

**国内源的坐标偏移是硬约束。** 天地图 CGCS2000 与 WGS-84 差异在百米级，高德 GCJ-02、百度 BD-09 有加密偏移。**这些偏移会直接污染涝点坐标**，而涝点坐标是本项目 17 个涝点的基础数据。规则：矢量与里程计算用 GCCS2000（WGS-84 与之在百米内可忽略），与高德/百度交互的结果必须显式转换后入库，禁止混存。

**天地图对本项目是最优解**：无需企业认证即可拿 7000 次/日、CGCS2000 与国土口径一致、免去 GCJ-02/BD-09 偏移处理。7000 次/日对本项目（涝点数量级 17，一次性建库）绰绰有余。

| 源 | 覆盖 | 用途 | 配额 | 密钥 | 接口 |
|---|---|---|---|---|---|
| **JPL Horizons** | 见第三节 | 观测者视角星历 | 见第三节 | 无 | 同上 |
| **JPL SBDB** | 见第三节 | 小天体物理与轨道 | 单请求串行 | 无 | 同上 |

这一方向整体与本项目无耦合。仅当讨论"台风—天文复合风险"（如天文大潮叠加风暴增水）时，Horizons 的日月位置计算才有意义。

## 六、按可用性排序

排序依据是**本项目实际瓶颈**，不是源的通用质量。本项目当前唯一卡死的是门槛 14/15 的输入层：降雨总量对官方实测 −46%，涝点水深命中率无基准可比。星历、天文观测两个方向全部排在后面，因为它们不参与任何门槛。

| 排名 | 源 | 方向 | 可用性 | 对本项目作用 |
|---|---|---|---|---|
| **1** | **CMFD v2.0** | 气象 | 开放获取、免 key、FTP 交付、74 年、融合台站观测 | **解锁门槛 14/15 的唯一正解**。只取 2021 年宁波域降水，约 10–20 MB |
| **2** | **Open-Meteo archive（ERA5）** | 气象 | **实测无 key 可通**，HTTP 200 | 立即可用。−23.7% 对 −46.0%，把输入偏差砍半；同时复现暴雨中心落区 |
| **3** | **天地图 API** | 坐标 | 免费 key、7000 次/日、CGCS2000 | 涝点建库与核验，免 GCJ-02/BD-09 偏移 |
| **4** | **MET Norway Locationforecast** | 气象 | 无 key、实测 200、20 req/s、CC BY 4.0 含商用 | 演示环境降级源与预报旁证；台风路径前置参考 |
| **5** | **和风天气 / 彩云天气** | 气象 | 有免费额度、需 key、国内精度高 | 官方预警（县级）与台风路径；分钟级降水可作短临补充 |

## 七、接入注意事项

**按依赖顺序，四条硬性要求：**

**CMFD 2.0 用 FTP 而非 HTTP API。** 申请账号需中国科技云通行证，用机构邮箱，注册后填数据用途说明，当天收 FTP 账号邮件。不要按 1.03 TB 规划磁盘，只取 2021 年 + 宁波域 + 降水率单变量。

**坐标必须统一在 CGCS2000。** 高德 GCJ-02、百度 BD-09 需显式转换后才能入库。涝点坐标是 17 个涝点的基准，一旦被偏移污染，门槛 14 的命中率判定全部失效。Nominatim 公共实例已实测不可用，不要放进降级链。

**MET Norway 必须配真 User-Agent。** `User-Agent: <应用名>/<版本> (<联系邮箱>)`。缺失或泛化 UA 在 2020 年起的新服务上是直接 403 封禁而非限流。守 `Expires` 头，命中时段内不得重复请求。坐标 4 位小数。

**Open-Meteo 免费层分端点。** 实测 `archive-api`（ERA5 再分析）无 key 可通，而 `forecast` 与 single-run（`/v1/ecmwf-hres`）需 Professional 档。搜索结果声称"Historical API 需付费"是不准确的，接入时按端点逐一实测。免费层整体标注非商业用途、数据 CC BY 4.0 需署名；服务端代码 AGPLv3，可自建以规避配额。

**JPL 系不得并发。** SSD/CNEOS Fair Use Policy 一次一个请求、须应用专用 User-Agent、不得嵌入网站。Horizons 参数须单引号（URL 编码 `%27`），返回须按 `$$SOE`/`$$EOE` 切分。
