# 提比翁 · 目标架构与里程碑（成熟 AI 产品）

时间 2026-10-16。性质：**目标架构**，不是现状描述。每条"已有/未建"均以工作区实测为准。
读者：产品与工程决策者。用途：作为后续所有施工的基准，避免"形态模糊"复发。

---

## 0. 产品定义（一句话）

**提比翁是一台"事件驱动的内涝对账机"**：一次事件进来，自动走完
**气象场 → 片区影响 → 岗位动作 → 观测回写**，
每一步都带出处与误差带，判据不足时**拒答并留痕**，多场事件后**变准**。

三类用户各拿一件：值班室拿**识别对照表**，规划岗拿**片区影响评估单**，巡查员拿**涝点卡**；
三件由同一份可复算底座与同一份**三腿对账索引**绑定。

**它不是**：预报系统、定级系统、调度系统、单点水深产品、聊天机器人。

## 1. 现状：四个交互环，只有两个闭合

```
腿一 气象科学 ──①降雨时空场──▶ 腿二 城建与土木工程 ──②影响读数──▶ 腿三 信息不对称 ──③动作/反馈──▶
   ▲                              │                              │
   └──────── ④观测回写 ◀──────────┴────────── 误差归因 ◀─────────┘
```

| 环 | 交互 | 实测状态 | 证据 |
|---|---|---|---|
| ① | 腿一 → 腿二：场换成损失 | **闭合** | ERA5 259 mm / 峰值雨强 6.12 mm/h → 涝点命中 0%、MAE 0.359 m、17 点**偏差全为负** |
| ② | 腿二 → 腿三：读数换成动作 | **闭合**（人工翻译像元号） | 28 张卡：5 可发 / 12 不采信模型 / 11 域外未计算 |
| ③ | 腿三 → 腿一：动作换成观测 | **断**（预留了列，无回写路径） | 卡的"人工核实并回报实况"无下游 |
| ④ | 腿三 → 腿二：口径控制出口 | **断**（仅文档规定） | `analysis/CONTEXT.md` 三层："腿一的误差必须经腿三的控制项才允许出口" |

**结论：现状是"模型 + Agent 形态评估文档"，不是 AI 产品。** 判据：AI 通道 0 个 key（门槛 24 BLOCKED）、反馈环 0 条、唯一真跑过的 AI（SAR U-Net）与主链零引用。

## 2. 目标架构：四层

```
┌─ L4 用户层：三个岗位界面 ───────────────────────────────────────────┐
│  值班室一页 · 规划岗一页 · 巡查员卡组      每件都可签、可追责          │
├─ L3 智能体层：转译与决策支持（当前空缺）─────────────────────────────┤
│  查数 → 判据核对 → 生成岗位动作 → 判据不足则拒答（护栏 R1–R4）        │
│  MCP 只读服务 7 工具已备 · 需 1 个 LLM 通道                          │
├─ L2 计算层：确定性内核 + AI 承重件 ─────────────────────────────────┤
│  图守恒律求解器（已有）· 27 条门槛（已有）· 面积型验证 SAR（已训未接） │
│  · 降尺度（计划中，当前不存在）                                      │
├─ L1 数据层：感知与观测 ────────────────────────────────────────────┤
│  ERA5 缓存（已有）· DEM（已有）· 28 条台账（已有）· 8 站（已有）      │
│  · SAR 影像（未接）· CMFD（公开可得未接）· 潮位（完全缺）             │
└──────────────────────────────────────────────────────────────────┘
        ▲                                                        │
        └──────────── ④ 观测回写（关键，当前为零）◀───────────────┘
```

### 2.1 AI 的位置（四处，且只有四处）

| # | 位置 | 环 | 现状 | 判据 |
|---|---|---|---|---|
| ① | 降雨降尺度与偏差订正 | 腿一入口 | **不存在**（ERA5 双线性 + 单站 51 分位映射） | 8 站 × 1 场 = 样本量不足；**关闭后系统仍可跑** → 不满足"AI 必要"，排最后 |
| ② | SAR 淹没范围反演 | 腿一观测 | **已训成、未接入**（7 折 val IoU 0.54–0.68 vs Otsu 0.12–0.31） | 面积型验证**不依赖点位精度**，正好补 17 点不足；注：训练域为全球事件，迁移宁波未标定 |
| ③ | 数字 → 岗位动作的转译 | 腿三出口 | **人工做** | 成熟 AI 产品的智能体就在这里；不是聊天框，是"带拒答的翻译器" |
| ④ | 观测回写与偏差归因 | 腿三→腿一 | **不存在** | "随使用变准"的唯一通道；缺它永远是计算器 |

### 2.2 成熟度五判据（可测，不是形容词）

| # | 判据 | 现状 | 目标 |
|---|---|---|---|
| M1 | 一次运行自动出结果 | ✗ 出 13 个 JSON，**人再翻译** | 一次运行直接产出三个岗位件 |
| M2 | 判据不足时拒答并留痕 | ✓ 护栏 R1–R4 已实现（**本项目最像成熟产品之处**） | 拒答须成为**一等产物**：生成"待核实工单"，不是静默跳过 |
| M3 | 每条结论带出处与误差带 | ✓ 双口径强制成对（门槛 18 判据本身需修，见 §4） | 误差带随件出现，不留 JSON 里 |
| M4 | AI 真承重 | ✗ 承重的是确定性算子 | ②③ 至少各一处 AI 在关键路径上，且**打不过基线就停用** |
| M5 | 随使用变准 | ✗ 反馈环为零 | ④ 回写 → 订正参数 → 下一场事件误差下降（按事件切分验证） |

**M1／M4／M5 是"好 Demo"与"成熟 AI 产品"的分界线。**

## 3. 产品的恒等对象：一次事件 = 一个对账件

```
事件（台风名 + 时段）
  ├─ A 场件   腿一：降雨时空场 + 联合分位数 + 已发布阈值越界对照（含"本模型不含潮位项"显式标注）
  ├─ B 评估件 腿二：片区四色面积构成 + Q(t) + 恢复次序 + 事件后加法分解
  ├─ C 动作件 腿三：涝点卡（复核类动作）+ 岗位动作清单
  ├─ D 回写件 ④ ：人工核实实况 → 观测约束（**当前为零，最小可运行形态见 §5-M2**）
  └─ E 索引   三腿对账索引：每条主张归哪条腿、判据出处、当前三态、依赖哪个外部读数
```

**判据：A–E 五件同批落盘、同 config_hash、互相可核对。** 现状只有 A/B/C 的散件，无 D、无 E。

## 5. 里程碑（四阶段）

每阶段以 **M 判据 + 可验收物** 定义，不看"写了多少文档"。

### P0 · 口径可信（0.5 天，零外部依赖）
- 交付：F1–F3 修完并重跑全链；`06` 与 `05` 结论一致；`07/08` 纳入指纹；域外卡"未计算"文案修正。
- 验收：`cli check` 与 `cli run` 结论一致；G21 通过；抽查三处表述无"已算零/未算"混淆。
- **不通过则后面全部无效**——因为产品的地基是"数字可信"。

### P1 · 闭环可跑（2–3 周，需 1 个 LLM 通道）
- 交付：L3 智能体层最小实现——MCP 7 工具 + 转译器 + 拒答为一等产物；一次运行产出 A/B/C/E 四件。
- 验收（用 `analysis/AGENT_FORM_EVAL.md` 已写好的 20 题对照）：形态 A（人读 JSON）vs 形态 B（问 Agent）的**耗时与正确率**；拒答率与误答率分列。
- 门槛：**B 形态在拒答正确率上不得低于 A**（宁可拒答，不可编造）。

### P2 · AI 承重（2–4 周，零新授权）
- 交付：② 接入——用已有权重对宁波出水面范围，接门槛 3 与面积型验证（IoU ≥0.5）；训练域差异显式标注。
- 验收：面积型验证有数；SAR 判读与内核淹没范围的重合率；若打不过 Otsu 基线则**停用并记录**（这条纪律是本项目的诚信资产）。
- 同时：潮位项进去或明写"不覆盖"——2021 烟花是风雨潮三碰头（增水 镇海 1.43 / 三江口 1.61 / 北渡 3.0 m），当前模型零潮位。

### P3 · 随用变准（4–8 周，需外部单位回写）
- 交付：④ 回写通道 + 按事件切分的验证协议；每场事件后误差指标进件。
- 验收：连续两场事件（**按事件切分，不按瓦片**）的 MAE 与命中率变化；若不变，如实写"未观察到改善"。
- 前置：至少一个外部单位书面确认参与（**这一条是组织前提，工程无法替代**）。

## 6. 与赛事三条方向/四条硬门槛的对应

| 赛事要求 | 由哪一层承担 | 现状 |
|---|---|---|
| 气候与地球系统模拟、AI 与决策支持 | L2 内核 + L3 智能体 | 内核强、智能体空缺 |
| 遥感、地球观测与全球环境变化监测 | L1 + ② | 已有可用 AI 资产，**未接入** |
| 气候风险、极端事件与防灾减灾 | L4 三岗位界面 + 拒答纪律 | 界面未成型，纪律已到位 |
| 问题真实 / 对象明确 | L4 | 对象明确，但"明确的对象"与"付费的对象"不是同一人（涝点卡用户是巡查员） |
| **AI 必要** | ②③ | **当前 FAIL**：主链无 AI；接入 ②③ 后可转 PASS |
| 90 天可小范围测试 | P0–P2 | 技术侧可达成；P3 卡在承接单位 |

## 7. 三条不可越的硬边界（架构层写死）

1. **致灾阈值与定级权威在发布方**（ADR 0003）：本产品只做对照与记录，**永不输出自定等级**。
2. **资源类指令不产出**（ADR 0002）：花钱或要权力的动作不由系统单发；台账未取得时按降级路径出"可参考"件并明标。
3. **单点级一律不主张**（ADR 0004/0005）：片区级可主张，单点级需管网与米级地形，当前不主张；"可发"标签必须随误差带出现。

## 8. 本架构的诚实边界

- P1 的真实前置是 **1 个 LLM 通道**；当前 0 个 key，门槛 24 因此整条 BLOCKED。
- P3 的真实前置是 **1 个愿意回写的外部单位**；这不是工程问题。
- ①（AI 降尺度）在 8 站 × 1 场样本量下做不出可信模型，且关闭后系统仍可跑——**故不排入 P0–P3，列为"暂不做"并写明理由**。
- 本文件所有"已有"均来自 2026-10-16 的工作区实测；所有"未建"均已在产物或代码中定位到证据位置。
