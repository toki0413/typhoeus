# 涝点卡与作业单分立，「转译卡」停用为交付物名称

时间 2026-10-16。决策人：用户（选项"拆成两个词"）。

## 背景

V4 §7.3 把转译层的差异化写成"六份可盖章的工程文件，其中预置方案单含泵站与移动泵车摆点坐标、台班数量、到达时限与责任人"；`docs/CONTEXT.md` 原「转译卡」条目把"动作+时限+口径+可见性+源指针"一并列为定义成分。

而盘上能产的转译形态（`typhoeus/cards.py`，28 张卡）只有查询、避险、对账记录号、卡片可信度、静默点转人工。**时限与责任人产不出来**：V4 §4.2 将排水管网与设施台账标注为"甲方提供"，本轮未取得；V4 §4.3 又把"撤离指令与安全责任判定"列为不覆盖，原话"系统给依据与建议，决策与责任在街道"。

压力场景把矛盾逼实：**FP001 鄞州大道（雅源南路）下穿立交，实测 0.68 m（红级），模型水深无记录（静默）**。这张卡若写"封闭该路段、派移动泵 N 台、区交警＋区水务局、+2 h 到位"，就需要资源台账、封路决定权与责任人名单三样都没有的东西；若曾按角色占位生成，会被自家门槛 20（无出处声明率 0/7）当场拦下。

## 决策

拆成两个术语，各带一条判据：

- **涝点卡**——现在能产。动作**只限复核类**：查、巡、报、避。不需台账、不涉决定权、不花钱。
- **作业单**——含资源类指令（摆点坐标、台班数量、到达时限、责任人）。前置条件为设施与管网台账，**当前不产出**，列为 V2 交付。
- **「转译卡」停用为交付物名称**，只作两者合称；凡出现必须指明指哪一个。
- 分级判据一句话：**这条动作要不要花钱、要不要权力——要，就不是系统发的。**

## 放弃的两种做法

1. **不拆词，把现有产物降格为"前身"**：定义保持纯净，但 V4 §7.3 那句"转译的对象是责任与动作，不是状态"当场失去指称对象，腿三在材料里无法署任何已实测的东西。
2. **按角色占位生成时限与责任方**（如统一填"区水务局、+2 h"并标"未经核实"）：这是把没有出处的数写进交付物，与门槛 20 和护栏 R3 的既有纪律冲突，且此前已被判定为编造。放弃。

## 后果

- 提交材料里腿三的措辞固定为：**涝点卡已实测（28 张，其中 23 张静默点转人工）；作业单待台账，属 V2**。V4 §四表 3 与 §7.3 凡是把"责任人/到达时限"写成当前能力的句子，都要按这条改写。
- 反向不可轻改：若将来把两者重新合称，材料里"含责任人与时限"的现在时描述会重新变成不实声明。
- 门槛 20 与护栏 R3 的判据需要覆盖作业单字段：台账到位之前，任何时限/责任人字段出现在产物里都应判 FAIL。
