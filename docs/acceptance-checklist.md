# 交付验收单

一套可复算的城市内涝决策链。**77 件产物、8 个只读接口、一条五步决策链。**

---

## 一、交付了什么

### 1.1 一条决策链：给定雨情 → 可执行的预案语言

```
给定面雨量 ──→ ① 分级 → ② 找病因 → ③ 定手段 → ④ 算门槛 → ⑤ 标可信度
```

| 步 | 它回答什么 | 落地产物 |
|---|---|---|
| ① 分级 | 该启动几级、派多少人、多少装备、多少布点 | `cli scenario` |
| ② 病因 | 这个点为什么淹（排水兜底 / 排水可挖 / 雨致 / 无汇流） | `p17` |
| ③ 手段 | 该用哪一类手段（按分型映射，不跨型套用） | `p32` 决策卡 |
| ④ 门槛 | 雨涨到多少会淹、排水要加多少 | `p21`–`p22` |
| ⑤ 可信度 | 这个结论能不能用；不能用的点给替代动作 | `p32` 逐点标记 |

**28 个点位逐行给出分型、翻转带、返还门槛、建议手段，每个点带可信度标记。**

### 1.2 一个不依赖雨量的入口

```
cli decide  ──→ 我还有几小时、我有几个人 → 逐条动作能不能做
```

| 动作 | 需时 | 判定 |
|---|---|---|
| 电梯停梯 | 1.0 h | 余量 10.5 h ✅ |
| 道路封道 | 2.0 h | 余量 9.5 h ✅ |
| 泵车调度 | 6.0 h | 余量 5.5 h ✅ |
| 人员转移 | 12.0 h | **缺口 0.5 h** ⚠️ |

**这是唯一不要求用户提供"他不可能知道的东西"的入口。**

### 1.3 投资方向的实证排序

| 结论 | 证据 |
|---|---|
| **先投排水** | 峰值 ×2.81、点位 ×5.46 —— **两个指标都第一**，稳健 |
| 次优：雨型 | 峰值 ×2.62，且决定"红格会不会出现" |
| 再次：潮位时程 | 红格杠杆 ×97 |
| 结构性解释 | 模型 85.4% 的雨量从管网排出 —— 管网是水的唯一主出口 |

### 1.4 跨事件与跨城市

| 项 | 结果 |
|---|---|
| 跨事件 | **18 场 / 36 年**，秩相关 **ρ = 0.9945**，分级与动作逐场一致 |
| 跨城市 | **5 城全部跑通**，工程泛化率 **1.0** |
| 四色面积 | 16 场实算，**8 场出现过红格** |

### 1.5 八个只读接口

`get_preset_plan` · `get_recovery_order` · `get_event_reconciliation` ·
`get_resilience_pricing` · `get_health_metrics` · `get_health_report` ·
`get_multievent_calibration` · `get_flood_cards`

**护栏在工具层（R1–R4），不在提示词层**：越域拒答 100%、弱基线拒答 100%、无证据声明 0/8。

## 四、已知限制（一次说清）

1. **点位水深分两层。** 原始模型水深不给（17 点命中 0%，MAE 0.359 m）；
   给的是**校正读数**（+0.359 ± 0.103 m，留一法 MAE 0.0909），
   只作与通报口径对齐，不是物理真值；观测越浅越过度校正。
2. **不给点位排序**。秩技能未建立（显著性随阈值变化），故排序建议由观测/台账决定。
3. **强对流不在覆盖内**（峰值低估 10.5 倍，缺雷达 QPE）。
4. **风驱雨与风暴潮未建模**；顶托是常数或合成时程，非实测潮位过程。
5. **27 条门槛里 7 条 BLOCKED**，逐条写明缺哪个外部读数——它们全部指向同一件事：**管网台账与雷达 QPE**。

**这些限制不是待修 bug，是能力的边界。边界之内，上面的五步链与投资排序可用。**
