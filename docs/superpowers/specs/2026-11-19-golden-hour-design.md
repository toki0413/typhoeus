## 1. 产品定位

### 1.1 是什么

一款单机离线的战术应急游戏，本质是应急安全科普教育产品。玩家扮演应急响应人员，在种子驱动的程序化灾害场景中经历"规划—执行"双阶段循环。

### 1.2 不是什么

- 不是预报工具，不是指挥调度系统。
- 不是医疗诊断工具，不给剂量处方。
- 不替代任何持证专业培训。
- 不复刻任何现有游戏的美术、叙事、音乐或关卡（MGS 只借设计语言）。

### 1.3 双主题

- **应急主题**回答"好不好玩"：战术深度、系统性沙盒、天灾压迫感。
- **教育主题**回答"对不对、有没有效"：对标权威标准、可导出评估的应急技能训练。

两者由一条原则贯穿：**玩家的每一个动作，既是战术动作，又同时产出一条学习证据。**

## 2. 设计支柱

每个系统都必须能指回以下五条之一；指不回去的，砍掉。

1. **给局势，不给清单。** 永远不展示任务目标列表。只给种子场景、被困者、有限资源与不完整信息。结算只统计救出人数与资源消耗。
2. **一个动作，两本账。** 每个可执行动作同时记录战术效果与学习证据；两本账互不干扰，玩家局内只见战术账。
3. **知识是生存条件，不是知识卡片。** 不做弹窗科普。不懂环境法则，环境直接让你付出代价。
4. **复盘才是教室。** 局内是应急，局后才是教育。对错只在行动后回顾中展开，且可一键跳过。
5. **大众硬件，专业内核。** 集显办公本 60fps；但判定规则、知识锚点、灾害参数对真实标准写。

## 3. 核心循环

### 3.1 单局结构

一局分五段：第 1–4 段是"玩"，第 5 段是"学"。

```
简报（不计时，1–2 min）
  └─ 规划（不计时，6–10 min）  ← 观察与决策
       └─ 执行（实时计时，18–24 min） ← 行动与后果
            └─ 结算（只报数，< 1 min）
                 └─ 行动后回顾（不计时，5–8 min，可跳过）
```

支持分幕存档：玩家可在任意幕间退出，下次继续。这是对"30–40 分钟长局"与"碎片时间"矛盾的缓解手段。

### 3.2 四幕内容

四幕横跨规划与执行两个阶段：第 I 幕主要发生在规划阶段，第 II–IV 幕发生在执行阶段。

| 幕 | 名称 | 玩家在做什么 | 教学重心 |
|---|---|---|---|
| I | 抵达与评估 | 侦察、建模、派令 | 决策性：信息不全下如何取舍 |
| II | 首次接触 | 执行任务队列、完成首批体感操作 | 程序性：关键动作的正确执行 |
| III | 局势反转 | 预埋事件爆发，被迫改令或硬撑 | 决策性：计划余量与临场调整 |
| IV | 撤离收尾 | 完成最后救援、控制暴露、撤出 | 陈述性：环境法则的最终检验 |

### 3.3 简报

种子揭示：灾害类型、环境类型、发生时段（白天/黄昏/夜间）、被困者规模、可调用资源、**信息噪声等级**。看完即进入规划，不可重抽。

### 3.4 规划阶段（不计时）

只做三件事，每件都有取舍：

- **侦察**。三类情报源：无人机（快、广、看不清室内）、窗口/楼栋观察（准、慢、受烟尘遮挡）、居民口述（免费、可能误导）。每次侦察只揭开一层信息，且消耗执行阶段的准备时间。
- **建模**。拼出威胁时钟进度、被困者位置与状态、可用通道、资源清单。态势图允许玩家手写标注。
- **派令**。给班组下达任务队列：去哪、干什么、带什么装备、什么条件下撤退。**不编排逐秒路径**，路径由班组在执行阶段自行完成。

关键体验：**信息永远不全，侦察永远不彻底，必须在某一刻拍板。**

### 3.5 执行阶段（实时计时）

- **威胁时钟**推进，只显示"安全 / 临界 / 危险"三段色带，不显示精确秒数；可因预埋事件跳变。
- **任务执行**。班组按队列行动，抵达**接触点**（破门、灭火、接触伤者、穿越烟区、破拆、绳索作业）时触发体感操作。操作正确则任务继续；错误则当场产生后果。
- **改令**。随时叫停重新下令，但叫停期间威胁时钟只减速不停止，并消耗**指挥余量**。改令次数越多，后续可调度空间越小。
- **预埋事件**。种子在时间轴上预埋 2–3 个事件，检验计划是否留有冗余。

### 3.6 结算

主指标只报两个：**救出 / 被困、资源消耗**。用时、次生伤亡、暴露峰值作为副读数呈现，不参与评分。

不给评分、不给评语、不给"正确做法"提示。这是"不给清单"原则的最后一道闸。

### 3.7 行动后回顾

复盘不是成绩单，是**第二局**。它由四件东西组成：

- **可拖动时间轴**：拖到任意时刻，查看当时的烟层、结构状态、队友位置与指令。
- **证据链**：点任一动作，展开"你做了什么 → 对应哪条标准 → 造成什么后果"。
- **伦理日志**：记录你放弃过谁、为什么。不给对错，只呈现事实，例如"15:20 你选择先救 401 的两名儿童，302 的老人等待了 4 分 12 秒"。
- **专家影子回放**：同一种子叠一条专家的动作时间线，标出双方在第几分钟分岔。v0.1 只手工录制一条。

**反事实**由同一确定性内核跑分支得出，只出结论、不做渲染。

支持**同种子重打**：看完全盘复盘后，用同一种子重来。此时变量只有玩家自己。这是"掌握"最诚实的验证方式。

## 4. 双主题缝合

### 4.1 缝合器：动作-知识绑定表

数据层中，每个可执行动作必须同时挂载战术效果与教学证据，缺一不可。

```ts
interface ActionBinding {
  actionId: string;
  label: string;
  discipline: 'fire' | 'flood' | 'snow' | 'typhoon' | 'quake' | 'wildfire' | 'hazmat' | 'compound';
  tactical: {
    target: 'hazard' | 'person' | 'route' | 'structure';
    effects: Array<{ field: string; delta: number; curve?: 'linear' | 'exp' }>;
    durationSec: number;
    cost?: { resourceId?: string; stamina?: number };
  };
  knowledge: {
    anchorId: string;              // 例：K-FIRE-03
    kind: 'procedural' | 'declarative' | 'decisional';
    standardRef: string;           // 实施阶段逐条核验后的标准条款引用
    difficultyTier: 1 | 2 | 3;
  };
  evaluator: Evaluator;
  evidence: { weight: number; minSamples: number };
  remediation: string;             // 复盘时对应的解释条目 id
}
```

### 4.2 五种判定器

| 类型 | 判什么 | 参数要点 | 典型动作 |
|---|---|---|---|
| `sequence` | 步骤与顺序 | 期望序列、容错步数 | 灭火器四步、担架固定、绳索下降 |
| `rhythm` | 频率/深度/间隔 | 频率区间、深度区间、判定窗口 | CPR 按压、人工呼吸、通风换气 |
| `position` | 位置、高度、朝向 | 规则谓词、宽限时间 | 低姿穿越、承重墙侧、上风向站位 |
| `choice` | 多对象间如何排序 | 选项集、评分细则 | 分诊四色、先救谁、破门或绕行 |
| `threshold` | 何时该做/该停 | 指标、安全阈值、迟滞惩罚 | 撤离时机、资源投入上限、放弃搜救判据 |

### 4.3 三类知识的呈现方式

- **程序性（怎么做）→ 体感操作。** 到接触点才出现，不讲解、不示范，只给目标与即时反馈。做对了局势好转，做错了当场付账。CPR 以节奏判定而非次数判定。
- **陈述性（是什么、为什么）→ 环境法则。** 从不口头讲解。烟气分层、承重构件、水流冲击、气流方向，全部以物理后果呈现。玩家被环境教育，而不是被文字教育。
- **决策性（何时、选谁）→ 情境压力。** 分诊、资源分配、撤离时机，全部置于信息不全与时钟压迫下。无提示，只有后果。

### 4.4 嵌入式复现

某个知识锚点反复出错时，模拟不弹窗提醒，而是在后续局势中**自然生成一次同类情境**加以复检。玩家不知道自己被补课，但会第二次遇到同一扇门、同一种烟、同一个岔路口。

这是环境化的间隔重复，也是教育闭环的核心机制之一。

## 5. MGS 化设计语言

借鉴 MGS 的四条基因——**威胁可读、可压制可恢复、工具即解法、环境会回应你**——不借其 IP。

### 5.1 暴露制（取代血量）

没有血条。三条隐藏暴露线：

| 暴露线 | 来源 | 超阈值后果 |
|---|---|---|
| 烟气剂量 | 停留于烟区、直立行走、未防护 | 视野收窄、咳嗽（暴露位置）、体感判定容差收紧 |
| 热负荷 | 接近火源、辐射热、防护不足 | 移动减速、操作抖动、判断提示延迟 |
| 体力/结构风险 | 负重、攀爬、进入受损结构 | 动作耗时增加、失误率上升 |

- 低于阈值可恢复；**累积不可逆**。
- 暴露不直接"扣命"，而是让玩家变慢、变笨、变不准。这使失败可承受，同时保持压迫感。
- 暴露状态直接影响体感操作的判定容差，形成状态与操作的耦合。

v0.1 取舍：三条线在数据模型中全部存在，但只对**烟气线**做完整调参与判定；热负荷与体力线以简化模型接入，后续版本补齐。理由是烟气线最能承载陈述性知识，也最容易被玩家直觉理解。

### 5.2 灾害警戒状态机

每种灾害拥有状态机：`安静 → 活跃 → 失控`，可被玩家行为压回。

- 压低手段因灾种而异：关闭防火门抑制火势、开窗排烟但可能助燃、堆沙袋减缓进水、清除可燃物延缓蔓延。
- 状态变化必须**可读**：烟色、热浪、结构异响、水位刻痕、风声变化，均为视觉/听觉线索，含静音替代方案。
- 由此形成 MGS 式节奏：**压制 → 通过 → 再压制**，而非一路推进。

### 5.3 招牌事件（Boss）

每个灾种定义一个高密度"遭遇战"，有可发现的规则、有多种解法、有明确后果。

| 灾害 | 招牌事件 | 可读线索 | 核心判断 |
|---|---|---|---|
| 城市火灾 | 回燃 | 门把温度、烟色、缝隙气流 | 现在开门还是再等 |
| 洪水内涝 | 溃口/急流窗口 | 水位速率、漂浮物速度、声音 | 涉水还是等舟 |
| 暴风雪 | 白盲 | 能见度、风向突变、体温下降 | 原地待援还是移动 |
| 台风 | 风眼窗口 | 风压骤降、雨停、云层 | 抢在风眼前还是风眼后 |
| 地震后救援 | 余震与二次坍塌 | 结构裂缝、异响、粉尘 | 进楼还是放弃 |
| 野火 | 飞火与风向反转 | 火线形态、风向、烟羽 | 守还是撤 |
| 化工泄漏 | 云团转向 | 风向、气味、颜色、比重 | 堵漏还是疏散 |
| 复合灾害 | 次生链 | 多时钟叠加与相互放大 | 资源在两条战线间分配 |

### 5.4 装备多用途

所有装备至少两种用途，允许玩家自行发明解法：

- 灭火器：灭火、砸窗、制造白雾遮蔽、临时支撑。
- 绳索：下降、固定、拖拽、警戒隔离。
- 撬棍：破拆、撬门、探测、支点。
- 湿毛巾：过滤烟尘、隔热、固定敷料。
- 无线电：求援、获取不确定情报、指挥队友。

### 5.5 情报与无线电

无线电只提供**不确定情报**，可能错误、可能过时，且从不说教。情报的价值在于让玩家练习"在噪声中判断"，而不是获取标准答案。

### 5.6 手工意图模板 + 程序化扰动

- 空间意图手工设计：必有一条"看似捷径实则死路"的通道、一处烟会先到的楼梯间、一扇能救命但需要判断的门。
- 种子只扰动参数：拓扑变体、出口状态、危险源位置、人群分布、事件时机。
- 原则：程序化负责变化，手工负责节奏。

### 5.7 灾害征兆语汇

灾害不是数值条，是**有行为语言的对手**。玩家不是读提示，是读现象。

| 灾害 | 征兆语汇 | 招牌遭遇的判断点 |
|---|---|---|
| 城市火灾 | 烟色由灰白转黑黄、门把烫手、门缝有"呼吸"声 | 回燃：现在开还是再等 30 秒 |
| 洪水内涝 | 水流声变调、漂浮物加速、井盖翻涌 | 急流窗口：涉水还是等舟 |
| 暴风雪 | 风声突然消失（白盲前兆）、呼出白雾打横 | 是否离开掩体 |
| 台风 | 风压骤降、雨停、鸟虫安静 | 风眼：抢前半段还是后半段 |
| 地震后救援 | 先到的竖向 P 波、粉尘、结构"呻吟" | 进楼还是封楼 |
| 野火 | 火线形态、飞火落点、烟羽倾斜 | 守还是撤 |
| 化工泄漏 | 气味、颜色、气体贴地还是上升 | 堵漏还是封控疏散 |
| 复合灾害 | 两个时钟互相放大 | 资源分给哪条战线 |

三条硬规则：

1. 每条征兆必须**可看、可听、可被静音模式替代**（视觉图标或字幕）。
2. 每个灾种至少三条征兆，且**征兆先于后果**，不能事后解释。
3. 征兆不弹窗、不标注"危险"，只呈现现象。

**招牌遭遇模板**（八灾种可复用）：3 个可读线索 → 1 个判断 → 至少 2 种解法 → 明确后果。回燃门是样板：门把温度、烟色、缝隙气流，三个线索指向"开/等"。

### 5.8 信息经济学

情报不是免费给的，是**用时间买的**。

- **时间银行**：每次侦察从执行阶段借走一段时间。界面不显示"剩余侦察次数"，只显示一条正在缩短的准备时间条。
- **证词网**：居民口述以"证词"挂在人物上，带置信度标签——目击 / 推断 / 传言。玩家无法直接验证真假。
- **假设与预期违背**：玩家可在态势图上标注假设（如"这扇门后是空房"）。假设错误时，环境给出反证（门后传来敲击声），而不是弹红字。
- **无线电延迟**：指挥中心回复有 5–20 秒延迟，且可能过时。等待回复本身就是成本。

### 5.9 建筑性格与结构听觉

老楼不是背景板，是**第三个对手**。

| 建筑性格 | 行为特征 | 教学点 |
|---|---|---|
| 预制板老楼 | 脆、易连续坍塌、接缝渗烟 | 承重构件与坍塌前兆 |
| 砖混老楼 | 烟囱效应强、竖向蔓延快 | 楼梯间与竖井风险 |
| 工业厂房 | 受限空间多、危险源集中 | 受限空间作业与洗消 |
| 学校医院 | 走廊长、疏散距离大、行动不便者集中 | 疏散组织与优先转移 |

- **结构听觉**：坍塌前必有征兆——钢筋的"叮"、混凝土的"沙沙"、粉尘落下。听得懂的人提前撤。
- **X 光视图**：切换后显示烟层高度、热区、结构应力色带，把"承重墙 vs 隔墙"变成一眼可见。
- **门与楼梯间是核心舞台**：门是判断点（温度、烟、背后有没有人），楼梯间是垂直战场（烟囱效应、唯一通道、坍塌风险）。

### 5.10 半自主班组

班组不是提线木偶。玩家下达**意图**而非路径：进入、搜索、救援、压制、撤离，附优先级与撤退条件。

- **能力画像**：新手会犹豫、老练会主动补位、疲劳会误判；无线电里能听出状态。
- **无线电沉默**：某一刻通讯突然中断。玩家无法判断是队友遇难还是进入信号盲区。这是零成本、高张力的设计。
- **指挥余量**：改令消耗的不是时间，是余量；余量见底时，队友开始自行其是。

### 5.11 3D 使用原则

- **90% 时间**：固定正交"娃娃屋"相机，可 90° 旋转，不允许自由飞行。楼层、烟层、楼梯间一眼可读。
- **10% 时间**：到达接触点切近景，完成灭火器、CPR、绳索等体感操作；近景只渲染当前房间，预算极低。
- **三种辅助视图**：剖面、X 光、烟层切片，全部服务教学而非炫技。
- **draw call 红线**：静态几何必须合并，同屏 < 150。实测 Three.js 摇树后仅 130KB gzip，瓶颈不在引擎，在渲染纪律。

## 6. 能力图谱（技能树）

### 6.1 定位

技能树不是战力树，是**能力图谱**。三个分支对应三类知识，节点直接映射权威能力项。

### 6.2 解锁语义

节点解锁的对象是**授权**，不是数值：

- 更高信息噪声的场景
- 更少的辅助提示
- 更严格的判定容差
- 更长、更复杂的威胁时钟
- 更稀缺的资源

### 6.3 掌握度

```
mastery = coverage × accuracy × stability
```

- `coverage`：该锚点在已玩种子中被触发的比例。
- `accuracy`：判定正确的比例。
- `stability`：跨种子表现的稳定性（1 − 方差）。

只在单一种子中做对不算掌握。无经验值、无刷分机制。

### 6.4 标准对标

- 锚点来源：红十字救护员课程（CPR/AED/止血包扎）、消防救援公众科普（灭火器与逃生）、应急管理部社区应急与避难场所知识等。
- **实施阶段逐条核验原始标准文本并登记条款号，禁止凭记忆写入。** 每条学习证据都必须可回指到具体条目。
- 设立专家复核环节，见 §8.3。

## 7. 灾害 × 场景矩阵

不是 56 个关卡，而是"灾害机制 × 场景几何"的组合生成。

### 7.1 八种灾害：四件套

| 灾害 | 主威胁时钟 | 环境法则（陈述性） | 关键动作（程序性） | 核心取舍（决策性） |
|---|---|---|---|---|
| 城市火灾 | 蔓延 / 轰燃 | 烟气分层上升、CO 中毒、回燃征兆 | 灭火器四步、低姿、门温试探 | 先灭火还是先疏散、破门时机 |
| 洪水内涝 | 水位 / 流速 | 30cm 流水可冲倒成人、井盖缺失、涉水导电 | 涉水探路、绳索保护、抛投救生 | 涉水还是等舟、先救高处还是近处 |
| 暴风雪 | 失温 / 能见度 | 风寒效应、白盲、雪坡风险 | 保温包裹、挖雪洞、路线标记 | 原地待援还是移动、燃料分配 |
| 台风 | 风眼窗口 | 风压、飞溅物、暴雨叠加 | 加固、避风位选择、断电 | 抢在风眼前还是风眼后行动 |
| 地震后救援 | 余震 / 结构 | 承重构件、燃气泄漏、二次坍塌 | 破拆支撑、生命探测、呼救 | 先救易救还是先救重伤、进不进危楼 |
| 野火 | 火线 / 风向 | 上坡加速、飞火、烟羽 | 防火隔离带、逆风撤离、防护 | 守还是撤、优先护哪片 |
| 化工泄漏 | 扩散羽 | 风向、气体比重、围堰 | 上风向撤离、隔离区、洗消 | 堵漏还是疏散、救人与封控冲突 |
| 复合灾害 | 多钟叠加 | 次生链（震→火→涝） | 跨灾种切换 | 资源在两条战线间分配 |

### 7.2 七类场景

| 场景 | 几何特征 | 人群特征 | 特殊约束 |
|---|---|---|---|
| 商务区 | 高层、玻璃幕墙、核心筒 | 白领为主、熟悉建筑 | 电梯禁用、疏散量大 |
| 老旧居民区 | 窄巷、自建房、通道狭窄 | 老年人与儿童比例高 | 消防通道占用、结构脆弱 |
| 工业园区 | 厂房、储罐、受限空间 | 工人、值守人员 | 危险源密集、洗消要求 |
| 学校医院 | 大空间、人群密集 | 行动不便者集中 | 转移优先级复杂 |
| 交通枢纽 | 大跨度、多出入口 | 流动人群、陌生人 | 信息传播快、踩踏风险 |
| 野外山区 | 无路网、地形起伏 | 驴友、村民 | 通信盲区、到达耗时长 |
| 沿海港口 | 码头、堆场、风浪 | 作业人员、船员 | 危险品堆场、撤离路线单一 |

### 7.3 种子模型

```ts
interface ScenarioSeed {
  seed: string;
  disaster: DisasterId;
  site: SiteId;
  timeOfDay: 'day' | 'dusk' | 'night';
  hazard: {
    intensity: number;          // 0..1
    spreadRate: number;         // 0..1
    scriptedEvents: Array<{ atSec: number; kind: string; payload?: unknown }>;
  };
  siteVariant: {
    topology: string;           // 手工模板变体 id
    exits: Record<string, 'open' | 'blocked'>;
    hazardPoints: Array<{ x: number; y: number; z: number }>;
  };
  people: {
    count: number;
    profiles: Array<{ ageBand: string; mobility: string; injury: string }>;
    hiddenSpots: Array<{ x: number; y: number; z: number }>;
  };
  resources: {
    crews: number;
    gear: Record<string, number>;
    etaSec: number;
  };
  information: {
    noise: 0 | 1 | 2 | 3;
    reconCost: number;
    misleadChance: number;
  };
}
```

**硬约束：同种子 + 同操作序列 = 同结果。** 固定步长、种子化随机，保证复盘反事实、同种子重打与逐帧确定性回放同时成立。

### 7.4 种子即故事

- **可读种子码**：如 `GH-FIRE-7F2A`，便于口头传播与课堂分发。
- **每日种子**：由日期确定性哈希生成，离线可用；全校或全社区可以在同一天打同一局势。
- **同种子重打**：先凭直觉，再看复盘，然后重来验证理解。
- **班级种子包**：教师导入一组种子，分别对应不同知识锚点，形成课程单元。

## 8. 评估与导出

### 8.1 两本账

- **战术账**（局内可见、结算使用）：救出 / 被困、资源消耗、用时、次生伤亡、暴露峰值、最大风险承担时刻。
- **学习账**（局内完全不可见、只进复盘）：每条知识锚点的覆盖、正确率、跨种子稳定度，以及**暴露来源归因**（本次伤害由哪条知识缺失直接造成）。

### 8.2 三层导出物

1. **单局复盘卡**：JSON（机器可读）+ 单页 HTML（可打印）。包含 2–3 个关键分叉点的反事实结局。
2. **班级/社区聚合**：匿名化掌握度热力图，直接对应"下一堂该讲什么"。
3. **审计接口**：导出判定规则与知识锚点映射，供领域专家复核。

所有导出默认本地生成，不联网、不上传。

### 8.3 专业审核流程

- 领域专家（消防、急救、应急管理）对每条判定规则逐条签字。
- 标准条款号在实施阶段核验原始文本后登记。
- 任何判定规则变更必须重新走审核。

## 9. 技术架构

### 9.1 约束

- 纯前端，零后端、零网络请求、零账号、零遥测、零第三方分析。
- 离线单包分发，双击即玩；允许 20MB 级资源包，不再强求 2MB 单文件。
- 面向集显办公本与低配设备；3D 渲染按低多边形预算设计，不追求写实材质。

### 9.2 确定性模拟核心

- 固定步长 20Hz 推进模拟状态，渲染插值。
- 种子化伪随机数（PCG 或 xorshift 族），全模拟唯一随机源。
- 回放 = 种子 + 输入日志。
- 模拟与渲染严格分离，模拟层不依赖 DOM。

### 9.3 模块边界

```
sim/      火、烟、水、结构、暴露、人群、任务队列的确定性推进
content/  灾害、场景、知识锚点、判定器、文案；全部数据驱动
eval/     判定器实现、证据聚合、复盘卡与反事实生成
ui/       态势图、执行 HUD、体感操作界面、复盘界面
app/      状态机、分幕存档、导入导出
```

每个模块对外暴露明确接口，可独立测试；`sim/` 不得反向依赖 `ui/`。

### 9.4 技术选型

- TypeScript。
- 场景渲染：Three.js（WebGL2），正交/等距"娃娃屋"相机；低多边形 + 烘焙光照。
- 明确禁用：实时阴影、体积光、光线步进烟雾、第一人称自由相机。
- 烟气表现：分层 billboard 粒子 + 高度切片几何体，不做体积渲染。
- 人群表现：InstancedMesh + 少量骨骼动画，禁止同屏高模。
- 界面与文本：原生 DOM HUD 叠加于 3D 画布之上，不引入重型框架。
- 音频：WebAudio，默认提供静音与视觉替代通道。
- 资源管线：glTF 使用 Draco / Meshopt 压缩，贴图使用 KTX2；压缩后总量目标 < 20MB。
- 打包：Vite 构建；渲染层只读 `sim/` 状态，不反向驱动模拟。

### 9.5 性能与可用性预算

| 指标 | 预算 |
|---|---|
| 帧率 | 1080p 集显稳定 60fps（低多边形、无实时阴影） |
| 安装包体积 | 压缩后 < 20MB；本地首屏可交互 < 5s |
| 渲染预算 | 单帧 draw calls < 150；同屏三角面 < 30 万；粒子 < 2 万 |
| 模拟规模 | 单场景人数、网格单元、粒子数量设硬上限 |
| 可玩性 | 全键盘可玩；色盲安全调色板；可调模拟速度；动效可关 |
| 音频 | 无音频可完整通关 |

## 13. 风险与待验证假设

1. **30–40 分钟长局 vs 碎片时间**：以分幕存档缓解，但需验证玩家是否真的会回来。
2. **体感判定宽容度**：过松无教学价值，过严劝退大众。必须通过可用性测试调参，禁止凭主观设定。
3. **暴露制的可理解性**：三条隐藏线对非玩家可能过于抽象，需要首局无痕引导（不弹教程）。
4. **程序化与手工的平衡**：种子过强会稀释手工节奏，过弱会失去重玩价值。
5. **教育效果归因**：跨种子提升是否真由理解带来，而非记忆特定种子，需要对照实验设计。
6. **3D 内容成本**：每类场景都需要建模，7 类场景的资产工作量约为 2D 方案的 2–3 倍，必须建立模块化资产库并复用构件。
7. **3D 可读性**：相机遮挡可能藏住被困者与烟层，需要剖面视图、透视或 X 光等辅助手段；需验证这些手段不破坏信息公平与教学判定。
8. **3D 晕动与无障碍**：正交相机可显著降低晕动，但仍需提供固定视角、可关动效与色盲安全配色。
9. **半自主班组的可控性**：自主性太低就变成提线木偶，太高会让玩家觉得"输给 AI"。需要调"听话程度"与"自行其是"的边界。
10. **伦理日志的调性**：呈现事实容易被读成道德审判。措辞必须中性、可跳过，且不进入任何评分。
11. **征兆的可读性**：三条线索若过于隐晦，玩家会归因为"运气"；若过于直白，就退化成提示。必须做线索强度分级测试。

## 14. 开放问题

- 复盘的"反事实"要出多少条分支，才能既说明问题又不淹没玩家。
- 专家影子回放需要多少条录制才够用，手工录制能否复用为教学素材。
- 证词网需要多少条证词才形成"真噪声"，而不是随机惩罚。
- 能力图谱是否需要对外开放导入（对标机构自有课程体系）。
- 标准条款引用的版权与引用规范，需在实施前确认。
