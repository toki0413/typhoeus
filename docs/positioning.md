# 产品定位与三个强调：扩展性、伦理、开放性

时间 2026-10-17。本文把定位写定，并为三个强调各给**实证**与**边界**——
不写成口号，因为口号在评审现场经不起一句追问。

---

## 定位

> **台风暴雨城市内涝风险推演与涝点决策支持。**

一句话展开：

> 给定一场台风暴雨的面雨量与时间分布，回答三件事：
> **哪些涝点必须动、该用什么手段、要做到什么程度**——
> 并且明确标出哪些结论能信、哪些不能。

**不做的**：实时调度指挥、施工图设计、跨灾种综合评估。

---

## 一、扩展性

### 1.1 已实测：换城市，内核零改动

| 项 | 读数 |
|---|---|
| 换城市 | 郑州 2021-07-20（未见过的城市） |
| 改了代码吗 | **没有**，只换 DEM 与降雨 |
| 结果 | 9.3 s 跑通，守恒残差 **7.02e-09**，峰值 0.827 m，红格 0.45% |
| DEM | AWS `copernicus-dem-30m` **匿名可取**，44.9 MB |
| 降雨 | Open-Meteo **免 key**，且主链已用最优的 `best_match` |

### 1.2 已实测：误差会被模型压缩

同一形状、幅度放大 k 倍（郑州地形，宁波参数）：

| k | 峰值雨强 | 面雨量 | 峰值水深 |
|---|---|---|---|
| 1 | 19.3 mm/h | 211 mm | 0.828 m |
| 3 | 57.9 | 633 | 1.337 |
| 10 | 193.0 | 2111 | **2.233** |

**深度标度指数 b = 0.434**：雨量放大 10 倍，深度只变 **2.72 倍**。

> 这不是巧合，是排水项 `q ∝ √h · h^(5/3)` 的自然结果——水越深排得越快。
> **它意味着：降雨驱动的幅度误差不会被线性放大到结论上。**
> 这是扩展性最实用的一条：数据不够好，结论退化得比预期慢。

### 1.3 已实测：形状可用、幅度可后置——但有精确条件

同一形状，幅度 k = 1…10：

| 量 | 跨度 | 判定 |
|---|---|---|
| **越阈累计雨量** | 22.1–33.1 mm，**跨度 49.8%** | ✅ **相对稳定** |
| 越阈时刻 | 3.33–15.0 h，**跨度 350%** | ❌ 高度敏感 |

**所以"先抓形状"的正确形态是**：

> 输出「**累计雨量到约 30 mm 时该点断行**」，而不是「**几点断行**」。

前者是模型内禀量，对幅度不敏感；后者必须配准的雨强。
这是强对流场景（幅度低估约 10 倍）下唯一还能站住的表述。

### 1.4 扩展性的边界（必须写进说明书）

| 维度 | 状态 |
|---|---|
| 换城市 | ✅ 工程可跑；❌ 参数需重标；⚠️ 台账是硬门槛 |
| 换事件 | ✅ 14 场标定，R² 0.883 |
| 换分辨率 | 🟡 54→30 m 仅改善 8% |
| 换降水类型 | ❌ **台风型可用；强对流不可用（峰值低约一个数量级）** |
| 换灾种 | ❌ 未测试 |

**扩展性的真实边界是"降水类型"，不是"城市"。**

## 二、伦理

这一项的实证不是我们"说了什么"，而是我们**放弃过什么**。

### 2.1 主动杀掉了一个对自己有利的结果

p25 序数技能检验：

```
全样本 n=17：ρ = +0.266，p = 0.302
宽松阈值：  ρ = +0.7147，p = 0.004   ← 看起来显著！
可辨阈值（≥1 mm）：n = 6，p = 0.182  ← 不显著
```

那个 ρ=0.72 / p=0.004 的结果**对我们极其有利**——它意味着"模型能给涝点排序"。
但我们做了阈值敏感性检验，发现它只在宽松阈值下成立，于是判定

> **「秩技能未确立，不给排序类建议」**

**这是本项目最硬的一条伦理证据**：我们有权发布一个漂亮数字，选择不发布。

### 2.2 把"缺数据"写成 BLOCKED，不写成推断

| 项 | 处理 |
|---|---|
| 10 条生命线断供记录 | 8 条在域外 → 可比较仅 1 条，判 **FAIL**，不静默外推 |
| 28 个涝点 | 11 个域外 → 台账保留、模型置空、标 `trust: 域外未计算` |
| 27 条门槛 | **15 PASS / 5 FAIL / 7 BLOCKED**，逐条写明缺哪个外部读数 |
| 149 点监测网 | 坐标与序列为合成 → 标 `provenance: synthetic`，绝不冒充实测 |

### 2.3 把拒答做进机制，不做进提示词

| 层 | 内容 |
|---|---|
| 工具层 | R1 越域 / R2 弱基线 / R3 单口径 / R4 调用预算，全部抛 `RefusalError` |
| 数据层 | 每张涝点卡带 `trust` / `trust_why` / `model_visible`；28 点中仅 **5 个**可见 |
| 门槛层 | G16 越界拒绝 **100%**；G17 弱基线拒绝 **100%**；G20 无证据声明 **0/8** |
| 说明层 | 工具描述写明"不回答单点水深绝对值"；payload 带 4 条读数规则 |

**伦理在这里不是自律，是架构。** 因为"提示词约束不住模型，而工具返回是确定性的"。

### 2.4 伦理的边界

- 我们没有第三方伦理审查，以上是**自我约束**。
- "不做实时调度"是能力限制的表述，不是伦理选择。
- 产品一旦进入政府使用，**误用的责任归属**未定义——这需要在交付条款里写清。

## 三、开放性

### 3.1 方法与证据开放

| 项 | 状态 |
|---|---|
| 许可 | **MIT**（`LICENSE`）+ `NOTICE.md` 列第三方条款 |
| 代码 | 56 个模块、1.4 万行，全部入库（327 文件） |
| 复算 | 双指纹 `config_hash 92cd76c2ea3f` / `source_hash 40d07eb29407b4b6` |
| 产物 | 32 件 `p*` + 8 件 `0*`，全部可由 `python -m typhoeus.cli run` 重生成 |
| 否决记录 | 5 条 FAIL 全部公开，不隐藏 |

### 3.2 数据源全部公开、免注册

| 数据 | 来源 | 门槛 |
|---|---|---|
| DEM | AWS copernicus-dem-30m | **匿名** |
| 降雨 | Open-Meteo archive/forecast | **免 key** |
| SAR | AWS sentinel-s1-l1c | **匿名** |
| 对比源 | CHIRPS / ERA5 | 公开 |
| 案例数据 | TPDC 元数据 | 已获（匿名接口） |

**核心计算不依赖任何 LLM API**——内核是确定性算子，LLM 只在编排层。

### 3.3 可互换性（开放的另一面）

- **降雨驱动可换**：`rainsrc.py` 抽象层，已实现 Open-Meteo / CMFD / CMPAS 三个读取器
- **DEM 可换**：任意 EPSG:4326 栅格
- **台账可换**：CSV 契约，字段有校验
- **不锁定厂商**：无专有格式、无云端依赖

### 3.4 开放性的边界（必须承认）

1. **数据不是我们的，不能替别人开放**——149 点真实坐标、管网台账、河网水位序列，都不在我们手里。
2. 代码是 MIT，但**本仓库尚未公开发布**（git 为本地）。
3. "开放"指的是**方法、证据、否决记录**，不是"数据全部公开"。
4. 第三方条款已在 `NOTICE.md` 列明，但**未做法律审阅**。

## 四、三项强调如何互相支撑

```
扩展性  → 换城市能跑、误差被压缩、阈值可移植
   ↓ 支撑
开放性  → 换数据源能换、指纹可复算、否决记录公开
   ↓ 支撑
伦理    → 因为都公开、都可复算，所以"不能说的话"是查得出来的
```

**顺序不能倒。** 没有可复算的指纹，伦理就只是承诺；
没有可互换的数据层，扩展性就只是口号。
