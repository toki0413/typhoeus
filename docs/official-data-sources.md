## 三、已接入：中央气象台台风网路径（`typhoeus/nmc_track.py`）

### 3.1 接口形态（实测）

```
年度列表  http://typhoon.nmc.cn/weatherservice/typhoon/jsons/list_<year>
路径详情  http://typhoon.nmc.cn/weatherservice/typhoon/jsons/view_<tid>
```

三个必须知道的坑：

1. **是 JSONP，不是 JSON**。
2. **两种端点括号层数不同**：`list_default` 是 `f(({...}))`，`list_2021` 是 `f({...})`。
   → 不数括号，直接取首个 `{` 到末个 `}`。
3. **点格式里经度在纬度之前**：`[id, "YYYYMMDDHHMM", epoch, 等级, 经度, 纬度, 气压, 风速m/s, ...]`
   → 与 `data.TrackPoint` 的字段顺序相反，是最容易写错的一处。已加自测专门判它。

### 3.2 自测结果（`python -m typhoeus.nmc_track`）

```
检索命中：烟花（In-fa）tid=2761203 code=2106
路径点 81 个，时间 202107161200 .. 202107310000
经度 116.6..134.8   纬度 18.8..40.1
PASS 经纬度顺序正确（经度在纬度之前）
PASS 覆盖 2021-07-25（宁波受灾日）
PASS 与 IBTrACS 同刻比对 81 点，位置偏差中位 0.100°、最大 0.566°
```

### 3.3 为什么这一条值得接

| 维度 | IBTrACS（现用） | 中央气象台（新增） |
|---|---|---|
| 机构 | NOAA 国际多机构合成 | **中国官方（WNP 区域专责中心）** |
| 点数 | 118（近岸加密） | 81（6 小时等间隔） |
| 时效 | 有发布滞后 | **实时可查** |
| 注册 | 免（已下载 109 MB） | **免** |
| 官方推荐 | 否 | **✅ 是** |

两者**同刻位置偏差中位 0.100°（约 11 km）**，最大 0.566°（约 63 km，出现在登陆附近）。
这是一次独立来源的交叉验证：两套官方最佳路径在影响宁波的时段内互相支撑。

> 材料里可以写：台风路径采用 **中央气象台官方路径**，并与 IBTrACS 交叉核验，
> 同刻位置偏差中位 0.100°。

## 四、仍然缺的两件（这两件才决定产品能不能升级）

### 4.1 河网水位 —— 顶托项唯一的实测边界

p30 的结论是：涝点中位高出河网 5.63 m，**仅 5/17 个点可能受潮位顶托**，
而有顶托才需要河网水位序列。**浙江省水利厅**是这条数据的正源。

现状：首页可达（134 KB，含"台风"×12），但「实时水情」子页 404。
**下一步要做的**：人工在 slt.zj.gov.cn 上找到"水情信息/实时水情/河网水位"的实际栏目路径，
或看是否有公开的 JSON 接口。

### 4.2 涝点台账 —— 分级与验证的入场券

郑州测试证明：换城市**工程上能跑**，但**没有本地台账就无法做分级与验证**。
宁波的 149 点监测网（市大数据局 + 市水利局）是真实存在的，
但**逐点坐标与逐时序列未公开**——本项目用的是合成台账。

**可能的新路径**：浙江省数据开放平台若开放「城市内涝积水点」目录，
是唯一可能拿到权威台账的公开渠道。但目录检索需登录，本次未探成。

## 五、对材料的三点直接用处

1. **赛道名称**：沿用官方的「**浙江台风内涝**」，比自造名字更容易对齐评审。
2. **数据来源可写**：台风路径用中央气象台官方接口（免注册）+ IBTrACS 交叉核验，
   这是**清单内来源**，不是野数据。
3. **缺口可写**：河网水位、涝点台账两项缺口，正源都在清单里（省水利厅、省数据开放平台），
   但都需要注册或线下对接——**这是"需要合作"的可核查表述，不是推脱**。

## 六、边界

1. 本清单是**社区帖子汇总**，非赛事官方文件；以官网最终说明为准。
2. 中央气象台接口为**未公开文档的内部接口**，随时可能变更；本模块失败时抛
   `NmcError` 而非静默降级。
3. 该站点证书链在部分环境不可验，本模块只读公开数据，故关闭证书校验并注明。
4. 未做登录态探测——浙江省数据开放平台与 data.cma.cn 的目录均需实名，本次未尝试绕过。
