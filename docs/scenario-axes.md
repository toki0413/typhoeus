# 情景四轴：降雨总量 / 降雨集中度 / 城建排水 / 土壤

时间 2026-10-17。产物 `out/p43_降雨集中度情景轴.json`、`out/p44_四轴杠杆对比.json`。
模块 `typhoeus/concentration.py`、`typhoeus/axis_leverage.py`。

---

## 一、为什么需要多于一条轴

此前所有情景只有一条轴：**面雨量总量**（p50/p80/p90/p95）。
但 p42 实测：域平均雨量完全不变、只改空间对比度时，峰值水深从 0.4928 翻到 1.0268 m。

> **「雨下得大」与「雨落得集中」是两条独立的放大器。**

而用户进一步问到了土壤与城建。所以本件把情景拆成**四条轴**，
并用一个统一基线的逐轴扫描，回答：**哪条轴真正控制结论。**

---

## 二、轴的定义

### A 降雨总量

沿用 p6 四档：**258.4 / 313.2 / 338.8 / 354.1 mm**（p50/p80/p90/p95）。

### B 降雨集中度（新）

乘子场用**确定性解析条带**，不用随机场（否则不可复算）：

```
m(x, y) = exp(a · sin(2πx/λ)) / mean(m)
```

- `a` 对比度振幅（本轴唯一参数），`λ = 0.35 域宽 ≈ 5.8 km`（落在雨带尺度内）
- `a = 0` 时 `m ≡ 1`（均匀）；`a` 增大则对比度增大，恒正、平滑

| 档 | a | 相对空间标准差 | max/min | ≥2 倍均值覆盖 |
|---|---|---|---|---|
| C0 均匀 | 0.00 | 0.00% | 1.00 | 0.0% |
| **C1 弱对比（≈现状）** | 0.25 | **17.68%** | 1.65 | 0.0% |
| C2 中等 | 0.50 | 34.55% | 2.72 | 0.0% |
| C3 强 | 1.00 | 64.21% | 7.39 | 10.7% |
| C4 极端 | 1.50 | 87.62% | 20.08 | 20.4% |

> **C1 的 17.68% 与实测现状 16.63% 吻合**——说明这套参数化能代表当前雨型，
> 且能往两端外推。

### C 土壤容量

30（现状薄土层假设）/ 120 / 600 mm（真实包气带量级）。

### D 城建排水

以**顶托高程**为代表：0.01 / 0.05（现状）/ 0.20 / 0.50 m。

> **为什么选顶托而不是不透水率**：p36 实测不透水率 +0.0016 m、糙率 +0.0009 m，
> 而顶托 +154%（p41）。**「城建」的代表参数必须选对，否则会得出错误的低敏感性。**

## 三、杠杆排序（同一基线：p90 / C1 / 30 mm / 0.05 m）

| 轴 | 峰值 min→max | **杠杆** | 红格 | 翻转 | 下渗变化 |
|---|---|---|---|---|---|
| **D 城建排水·顶托** | 0.3937 → 1.1073 | **×2.81** | 0 → **1098.4 ha** | **是** | — |
| B 降雨集中度 | 0.4262 → 0.6999 | ×1.64 | 0 → 0.9 ha | 是 | — |
| A 降雨总量 | 0.4206 → 0.5006 | ×1.19 | 0 → 0.3 ha | 是 | — |
| C 土壤容量 | 0.4753 → 0.4804 | **×1.01** | 0 → 0 | **否** | 54 → 930 万m³（**17 倍**） |

### 三条硬结论

1. **城建排水是压倒性主项**（×2.81），是降雨总量（×1.19）的 **2.4 倍**。
2. **只有城建排水轴能造成大面积红格**：1098.4 ha（全域 10%）；
   其它轴最大只到 0.9 ha。
3. **土壤轴不造成红格翻转**（×1.01），但**下渗量变化 17 倍**。

## 四、这改变了"什么重要"的直觉

> **降雨是最容易被讨论的轴，却是杠杆最小的轴。**

| 轴 | 谁能回答它 | 数据可得性 | 杠杆 |
|---|---|---|---|
| A 总量 | 气象模式预报 | ✅ 易 | ×1.19 |
| B 集中度 | **雷达 / 短临** | 🟡 需实名 | ×1.64 |
| **D 城建排水** | **管网台账 / 河网水位** | 🟡 河网水位有公开通道 | **×2.81** |
| C 土壤 | 土壤剖面 / 遥感 | ✅ 遥感可做 | ×1.01（峰值） |

**所以"哪条轴最值得去要数据"的答案是：城建排水——它杠杆最大。**
而它恰好也是我们唯一还缺的那块（河网水位的公开通道已定位，见 `official-data-sources.md` §7）。

---

## 五、四条轴的正确用途（不能混用）

| 轴 | 用来回答 | 不要用来回答 |
|---|---|---|
| A 总量 | "这场雨有多大" | 淹没格局 |
| B 集中度 | "雨落在多大面积上" | 绝对水深（合成雨带非实测） |
| **D 城建排水** | "为什么同雨不同淹" | 水量去哪了 |
| C 土壤 | **"水量去哪了"（审计）** | 淹没判据 |

**这是本件最实用的一条：土壤轴应做成「水量审计轴」，不是「淹没判据轴」。**
把它混进淹没判据，会得到"土壤几乎不重要"的错误结论；
而做成水量账，它给出 17 倍差异。

## 七、边界

1. 四条轴**逐轴单独扫**，不是正交分解——轴间可能有交互，本件未测。
2. 集中度为**合成条带**，不是真实雨带，也不是下采样结果。
   它的用处是把"我们缺什么"变成可操作的敏感性维度，**不是声称已解决雨型问题**。
3. 条带方向固定沿 x 轴；真实雨带的走向与移动未建模。
4. 土壤只改容量，未改 Ksat / 吸力头（见 p36 的接线问题）。
5. 城建只改顶托，未改导水系数（p36 显示两者量级相当，此处用一个代表）。
6. 基线取 p90 + C1；换基线后排序可能变化。
7. 共用宁波参数，无本地验证；**本件不进本次提交材料（技术冻结）**。
