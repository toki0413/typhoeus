# 两个站点有没有可用数据集：没有，但挖出一个真线索

时间 2026-10-18。实测两站形态与可取内容。

**结论：`www.dapiya.cn` 与 `www.smca.fun` 都**没有**我们缺的数据集。
但 `smca.fun` 的前端代码里指向了一个**可达、免注册**的台风数据库（Digital Typhoon），
那是本次唯一的真线索。**

---

## 一、`www.dapiya.cn`：台风爱好者站点，数据是**图像 + 最佳路径**

### 它有什么

| 栏目 | 内容 |
|---|---|
| 气象卫星云图 | 实时与存档（`data.dapiya.cn/history`、`archive.dapiya.cn`） |
| 数值预报 | 模式图（`model.dapiya.cn`） |
| **数据存档** | `data.dapiya.cn/Archive/` —— 按风暴号分目录（1851、1852…） |

### 存档里到底是什么（实测）

`Archive/1851/` 下是：

```
bal011851.dat   1.4 KiB
bal021851.dat   100 B
bal031851.dat   100 B
bal041851.dat   4.8 KiB
bal051851.dat   1.6 KiB
bal061851.dat   1.7 KiB
```

**这是 JTWC/ATCF 最佳路径格式**（`bal` + 洋区/编号），即**路径与强度**记录。

### 为什么不可用

| 原因 | 实测 |
|---|---|
| **不是雨量** | 最佳路径只有经纬度、风速、气压，没有降水场 |
| **下载被拦** | 直接 GET `bal011851.dat` 返回 **HTTP 567**（非标准状态，疑为防盗链） |
| 云图/模式图是 **PNG 渲染图** | 不是数值场；从色标反演误差不可控 |
| 模式图接口不可用 | `model-api.dapiya.cn/` 只返回 `Hello World`（11 B）；`latest.txt`、`model-imgs` 均失败 |
| 与既有数据重复 | 我们已有中央气象台最佳路径 + IBTrACS（同刻偏差中位 0.100°） |

---

## 二、`www.smca.fun`：**不是数据提供方**，是前端聚合

### 形态（实测）

| 项 | 结果 |
|---|---|
| 服务端渲染 | **无**。所有路径（`/`、`/docs`、`/sitemap.xml`、`/robots.txt`、`/manifest.json`）都返回**同一个 5 965 字节 HTML 壳** |
| 渲染方式 | 纯前端 SPA，`/js/index-DxdHXRJ4.js`（2.9 MB） |
| 常见 API 路径 | `/api`、`/api/v1` 均 **404** |

### 它的数据从哪来（从 JS bundle 里读出来）

bundle 内 131 个 URL，指向的是第三方：

| 源 | 说明 |
|---|---|
| `agora.ex.nii.ac.jp/digital-typhoon` | **Digital Typhoon**（日本国立情报学研究所） |
| `data.cma.cn` | 中国气象数据网（**需实名注册——已知不可用**） |
| `www.nmc.cn` | 中央气象台（我们已在用） |
| `yandoos.balabot.top` / `bamc.top` | 第三方服务 |

> **它自己没有数据集，也没有公开接口。** 它是个"天气栈"前端，
> 消费别人已经公开的源。

## 三、但顺带挖到一个真线索：Digital Typhoon

`smca.fun` 引用了它，我顺手测了可达性：

| URL | 结果 |
|---|---|
| `https://agora.ex.nii.ac.jp/digital-typhoon/` | **200**，35635 字符（首页） |
| `.../summary/wnp/s/202106.html.en` | **200**，21565 字符，标题 |
| | **「Digital Typhoon: Typhoon 202106 (IN-FA)」** |

**它免注册可达，而且有我们那场事件（2021 烟花）的专门页面。**

### 它有什么

- **最佳路径**（1951 年起）
- **卫星云图存档**（1978 年起，Himawari/GOES 系列）
- 台风目录与统计

### 对我们有用吗（诚实判断）

| 我们缺的 | Digital Typhoon 能给吗 |
|---|---|
| 雷达 QPE | ❌ 没有 |
| 逐时格点降水 | ❌ 没有（只有云图与路径） |
| 管网台账 | ❌ |
| 河网水位 | ❌ |
| **最佳路径** | ✅ 有——但与 IBTrACS 重复 |
| **卫星云图** | 🟡 有——**可以作为降水代理**，但要自己标定 |

**唯一有潜在价值的是"云图→降水"这条路**：红外云顶温度与降水强度有经验关系
（如 GPI、Scofield 方法）。但它需要标定，而**标定需要雷达或雨量站**——
又绕回我们拿不到的那两样。

> **所以 Digital Typhoon 是"可达但不对症"**：
> 它是路径/云图库，不是降水场库。

---

## 四、判定

| 站点 | 有可用数据集吗 | 理由 |
|---|---|---|
| `www.dapiya.cn` | ❌ **没有** | 只有最佳路径（被防盗链）与 PNG 渲染图 |
| `www.smca.fun` | ❌ **没有** | 前端聚合，无自有数据、无公开接口 |
| `agora.ex.nii.ac.jp/digital-typhoon` | 🟡 **有，但不对症** | 路径与云图可达免注册；无降水场 |

### 与既有四轴缺口对照

| 缺口 | 杠杆 | 这两站能补吗 |
|---|---|---|
| 城建排水（顶托/管网） | ×2.81 / ×5.46 | ❌ |
| 降雨集中度（雷达 QPE） | ×1.64（峰值）/ ×1.12（点位） | ❌ |
| 降雨总量 | ×1.19 | ❌（我们已有 Open-Meteo） |
| 土壤 | ×1.01 / ×1.14 | ❌ |

**一个都不补。**

---

## 五、边界

1. 本文只做了**可达性与内容形态**的实测（HTTP 状态、文件列表、格式判读），
   **未注册、未登录、未绕过任何访问限制**。
2. dapiya 的 HTTP 567 是站点侧返回；成因（防盗链/限流）为**推断**，未证实。
3. Digital Typhoon 只测了 3 个 URL 的可达性，**未系统核对其数据授权条款**；
   若要使用须先读其使用条款。
4. 「云图→降水」需标定这一点是**常识性判断**，本文未做任何实验。
5. 本文不评价两站的运营与内容质量，只判断"能否补我们的数据缺口"。
