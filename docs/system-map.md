```
┌─────────────────────────────────────────────────────────────────┐
│ ⑦ 服务层     MCP 8 工具 + 护栏 R1–R4                            │
```

**一条主链**：输入 → 内核 → 参数 → 决策 → 判据 → 产物 → 服务。

## 二、逐层实况

### ① 内核层（4 个模块）

| 模块 | 作用 |
|---|---|
`kernel.py` | 图守恒律求解器：格点通量 `q=(1/n)h^(5/3)√S`，Green-Ampt 入渗，Ghil-Sellers 能量平衡 |
`config.py` | 四层参数 + `config_hash` |
`soilcal.py` | **土壤前期状态的观测标定**（新增） |
`measure.py` | 测度与分位 |

**关键性质**：纯 CPU、零 API key、确定性；水量闭合（守恒残差 ~1e-10）。

### ② 参数层（49 个参数，四层）

| 层 | 个数 | 管什么 |
|---|---|---|
| L1 物理 | **5** | 重力、Manning、CC 标度 |
| L2 场地 | **27** | 降雨源、域、DEM、排水、入渗、土壤、辐射 |
| L3 策略 | **10** | 集合成员数、预算、残差门、三份额分解 |

> **L2 是唯一依赖本地条件的一层**（27 个参数），也是"换城市要重标"的具体位置。

## 五、这套体系**不是**什么（同样是体系的一部分）

| 不是 | 原因 |
|---|---|
| **不是韧性评估器** | 韧性是时间积分，我们只给峰值与本底；缺恢复曲线 `Q(t)` |
| **不是预报系统** | 输入是"给定降雨"，不是"预测降雨" |
| **不是数字孪生** | 无实时耦合、无传感反馈 |
| **不是点水深工具** | 17 点命中 0%，28 点仅 4 个可承载建议 |
| **不覆盖强对流** | 峰值低估 10.5 倍（无雷达 QPE） |
| **不含两相载荷** | 台风是雨/潮/风三相，我们只建了雨相；顶托（×2.81，潮的函数）仍是常数 |

---

## 六、一句话

> **这是一个"给定降雨 → 分型 → 手段 → 门槛 → 可信度"的可复算决策链，
> 用七层结构支撑，靠双指纹自证、靠工具层护栏拒答、靠免注册数据保持可复算。**
>
> 它的强项是**诚实边界**与**跨事件可复现**；
> 它的短板是**没有恢复时间轴**与**只建了一相载荷**。
> 两者都必须随产品一起交付，否则它会被误读成一个预报器。

## 七、最近两次事故的教训（写进体系文档）

| 事故 | 表现 | 教训 |
|---|---|---|
| 指纹被扫入 | `config_hash` 静默变化，8 处材料引用失效 | 他人活跃时不可 `git add -A` |
| 工具被覆盖 | MCP 工具 8→7；G18 分母 5→4，**仍显示 PASS** | 绿灯可能来自覆盖率缩小 |

**第二条尤其值得记**：门槛全绿不等于覆盖完整。
所以本体系的所有门槛都必须**同时报告分母**——G18 现在写的是"100%（5 份）"而非裸比率。
