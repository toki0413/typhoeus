# 金色时刻 / Golden Hour — 长期路线图

> 目标不是“再做一段剧情”，而是把游戏从**决策看板**改成**可自由行动的系统性火灾沙盒**。
> 借鉴塞尔达的是“系统互作 + 多解 + 自由路线 + 环境即提示”，不是开放世界、耐久度或战斗。

---

## 1. 北极星

一栋可以自由进出的居民楼火灾沙盒。玩家只有有限工具，靠对火、烟、热、风、水、结构的理解，
自己决定从哪进、怎么救、先救谁、什么时候撤；同一个目标至少有三条可行路线/三种解法，
系统会对每一个动作做出符合直觉的连锁反应。

### 设计支柱（取）

1. **系统优先于脚本**：火 / 烟 / 热 / 氧 / 风 / 水 / 门 / 窗 / 材料共用一套规则。
   不写“这扇门只能这样开”，只写门的材料、温度、缝隙和两侧气压。
2. **多解**：门、窗、墙、火、被困者，每个障碍至少三种有效动词。
3. **自由路线**：水平 + 垂直移动（楼梯、消防梯、窗、破拆、屋顶），用体力和负重限制，
   而不是空气墙。
4. **环境即提示**：烟色、热浪、门把温度、声音、材料变化告诉玩家系统状态，不用任务箭头。
5. **代价与取舍**：水、灭火器、破拆工具、时间、体力都是资源；快不等于安全。

### 明确不做（舍）

- 不做开放世界、不做耐久度、不做战斗循环、不做“爬一切”。
- 不做完整 CFD/刚体物理；用房间图 + 粗网格 + 分层烟层，保证浏览器性能和可读性。
- 不丢掉消防员的专业动词：测温、回燃判断、低姿、通风、破拆仍然是核心。

---

## 2. 现状基线（已具备）

- 2 层剖面楼、202 房间、主楼梯 + 消防梯、楼梯坍塌事件。
- 玩家直接操控班组（WASD / 方向盘 / 上下文动作键）。
- 开门 → 触碰 / 等待 / 回燃；背人撤离；双出口。
- 房间级切镜、烟层视觉、浓烟暗角、体力/暴露 HUD。
- 门禁：`check`（148+ 测试）、`verify:visual`、`verify:audio`、包体预算。

### 关键缺口

- 模拟是**集中式数值**（`fire: number`、每层 `smoke[]`、`heat[]`），火不会在房间里蔓延，
  烟不会顺着门缝/窗户走，水/破拆没有空间效果。
- 移动是**区域约束**（走廊 + 202 房间），没有真正的房间图/碰撞/垂直攀爬。
- 工具只有“压制火势”这个抽象按钮，没有水枪、灭火器、破拆、排烟的空间效果。
- 内容仍是**单场景脚本**，不是一个可反复进入的沙盒。

## 3. 目标循环（一次 5–8 分钟）

1. 到场：看到烟气从哪层哪扇窗出来，判断入口（正门 / 消防梯 / 后院窗 / 屋顶）。
2. 进楼：选择路线和节奏；烟层高度、温度、体力、负重实时影响能走哪。
3. 侦察：贴门测温、听声音、看烟色；判断回燃/轰燃/结构风险。
4. 处置：冷却、排烟、破拆、绕路；每个动作都会改变场内的火、烟、风。
5. 搜救：找到居民，选择背/扶/引导；居民会恐慌、躲藏、被烟逼退。
6. 撤离：路线可能被火/烟/坍塌改变；资源不够时要放弃某些目标。
7. 复盘：用行动轨迹、暴露曲线、火场演化对比解释“为什么是这个结果”。

---

## 4. 自由度预算（Freedom Budget）

| 维度 | 玩家可决定 | 系统固定 |
| --- | --- | --- |
| 路线 | 正门/消防梯/窗/破拆/屋顶 | 建筑结构、火与烟的物理 |
| 节奏 | 快冲 / 低姿 / 等待 / 撤退 | 体力、烟毒、热暴露的代价 |
| 工具 | 水、灭火器、破拆、排烟、热像 | 工具的容量、重量、生效条件 |
| 救援 | 先救谁、背还是扶、是否二次进入 | 居民行为与伤情恶化 |
| 结果 | 救出几个、付出什么代价 | 火场演化与结构失效 |

## 5. 目标架构

```
src/sim/
  spatial/          # 新：空间化火灾模拟
    fields.ts       # 房间粗网格：燃料/热/烟/氧/水/结构
    spread.ts       # 火蔓延、烟浮力、通风、回燃、蒸汽
    materials.ts    # 材料表：可燃性、导热、强度、烟产率
    rooms.ts        # 房间图：门/窗/墙/楼梯/竖井，连通与气压
  interaction/      # 新：动词与可交互物
    interactables.ts# 门/窗/墙/消火栓/灭火器/居民/家具
    verbs.ts        # 测温/开门/通风/冷却/破拆/背负/引导
  nav/              # 新：可行走图与移动
    graph.ts        # 房间节点、门洞、楼梯、窗、梯子
    movement.ts     # 碰撞、攀爬、负重、体力
  state.ts          # 兼容层：给 HUD/复盘提供聚合值
```

- **模拟频率**：场 5–10 Hz 固定步长，渲染 60 Hz；必要时放 Web Worker。
- **网格粒度**：每房间 0.5–1 m；烟用 2–3 层高度层，不做体素 CFD。
- **确定性**：种子 + 输入日志可重放，支撑测试与复盘。
- **内容数据化**：房间、材料、道具、初始火情用 TS/JSON 定义，场景只给种子和初始条件。
- **渐进迁移**：保留现有 2 层切片当“教学关”，新系统用特性开关并存，避免一次性推倒。

## 6. 阶段与任务

### Phase 0 — 单房间系统原型（先验证“好不好玩”）

目标：一个 6×6 m 房间，验证系统互作与多解，不追求美术。

- [x] 空间场：燃料/热/烟/氧/水/结构，8×8 粗网格
- [x] 火蔓延 + 门/窗通风 + 回燃 + 水冷却
- [x] 蒸汽（水遇到高温的蒸发与能见度反馈）
- [x] 可交互物：门（测温/开/破拆）、窗（开/破）、沙发（A 类燃料）、油桶（B 类液体）
- [x] 灭火剂 × 火类矩阵（A/B/C/D/E/F × 水/泡沫/干粉/CO₂/湿化学/沙土/覆盖）
- [x] 器材状态：过期 / 压力不足 / 破损 / 用空，用错与失效都有解释
- [x] 就地取材：湿棉被、锅盖、食盐、水桶、湿毛巾、断电、关门、破窗
- [x] 玩家移动 + 低姿；烟/热暴露累积与倒地
- [x] 背负 / 引导被困者：健康衰减、负重、最近已开出口撤离
- [x] 三种解法都能成立：
  - 冷却门 → 开门进入
  - 先开窗排烟 → 低姿进入
  - 直接灭火源 → 清理通道
- [x] 确定性测试：同一初始条件，三种解法产生不同但可解释的场演化
- [x] 单房间可玩切片：`room.html`（WebGL 不可用时自动降级 Canvas2D 俯视图）
- [x] 按入口拆分包体预算：main / room / building / three.module + 总计

**当前状态**：Phase 0 + 0.5 已完成。模拟核心、器材与就地取材、蒸汽/能见度、玩家姿态与暴露、
被困者健康与背负撤离、可玩切片闭环、确定性测试与按入口包体预算均已落地。
下一步进入 Phase 1：房间图、可行走图、三条到 202 的路线与建筑切镜。

**验收**：不看攻略，三个测试者能各自找到不同解法；复盘能解释每条路线的代价。

### Phase 1 — 建筑与自由路线

- [x] 3 层、楼梯间、消防梯、屋顶；房间图与连接（8 户完整户型、后院留到内容阶段）
- [x] 可行走图：门洞、楼梯、梯子、窗、破墙；体力与负重限制
- [x] 相机：每房间确定性机位 + 烟浓度贴近/压低（`buildingCam`）
- [x] 至少 3 条到 202 的路线，耗时/风险不同
- [x] 可玩建筑入口 `building.html`：四层视图、路线选择、背人撤离
- [ ] 8 户完整户型、后院、通风图

**当前状态**：Phase 1 核心已完成。房间图、路线搜索（主楼梯 / 消防梯 / 破拆三条到 202）、
上下楼体力成本、每段行程结算、建筑切镜数据与可玩建筑切片均已落地；
248 项测试与三个入口的构建/包体门禁通过。

**验收**：同一目标可用主楼梯、消防梯、外墙窗/梯子三条路线完成；路线测试与可视化门禁通过。

### Phase 2 — 工具与多解矩阵

- [x] 水枪/水带、灭火器、破拆斧、排烟机、热像仪
- [x] 梯子/绳的工具、重量与装备模型（路线接入留到后续阶段）
- [x] 每个障碍 ≥3 个有效动词；动词改变场，而不是播放动画
- [x] 资源：水量、灭火器当量、工具重量、携带上限
- [x] UI：上下文动词 + 工具轮盘；不用长菜单

**当前状态**：Phase 2 核心已完成。17 个动词覆盖门/窗/墙/火/居民；
携带工具、重量、装备/卸下、条件折扣、按次消耗、热像扫描、排烟、破拆均已落地；
单房间切片的旧工具面板已替换为工具轮盘。273 项测试与三个入口的门禁通过。

**验收**：解法矩阵测试覆盖门/窗/墙/火/居民；每个动词都有可测的场变化。

### Phase 3 — 居民与压力

- [x] 居民 Agent：恐慌、躲藏、跟随、被烟逼退、伤情恶化
- [x] 多人救援：先救谁、背/扶/引导、二次进入
- [ ] 声音/光线/烟色作为主要信息通道；无线电只给方向性建议（留到 Phase 5 内容打磨）
- [x] 失败由系统产生（烟毒、热、坍塌、回燃），不是对话选项

**当前状态**：Phase 3 核心已完成。居民 Agent（恐慌避险、躲藏搜索半径、失去意识、伤情与死亡宽限）、
多人救援（优先级、牵/背、同种子不同顺序 0–3 人）、系统致败与建筑入口三人救援切片均已落地；
空呼保护让消防员能支撑多次进出，但烟热仍在累积。297 项测试与门禁通过。

**验收**：同一次火场能救出 0–3 人，结果差异来自行动而不是剧本分支。

### Phase 4 — 沙盒事件与复盘

- [x] 事件导演：风向变化、窗户失效、楼梯/楼板按热与结构失效
- [x] 场景 = 种子 + 初始条件 + 建筑布局，而不是时间轴脚本
- [x] 复盘：路线回放、火场演化对比、因果解释（暴露曲线可视化留到 Phase 5）
- [ ] 训练模式：程序化演练（测温、回燃、低姿、破拆）

**当前状态**：Phase 4 核心已完成。事件导演按 15s/30s 固定日程切风，窗户高温失效，
结构 < 0.35 且热 > 0.6 连续 6 秒坍塌并封锁相邻连接；种子 + 输入日志回放得到可哈希的场序列；
旅行与救援记录前后场快照，结算时输出可指到动作 id、时刻与场变化的因果复盘。
314 项测试、三个入口构建与包体门禁通过。

**验收**：同种子不同打法产生不同的火场演化与复盘结论；复盘能指到具体动作。

### Phase 5 — 内容与打磨

- [ ] 3–5 个户型、家具/材料/居民组合；教学关用“演练”而不是文字
- [ ] 美术/音频/性能预算；可访问性；存档/中断续玩
- [ ] 叙事：无线电、邻居、楼长；把“为什么进火场”讲清楚

**验收**：一局 5–8 分钟，稳定 60fps（桌面），移动端降级可玩；完整门禁绿。

## 7. 质量门禁（贯穿）

- **模拟单测**：场更新、火蔓延、通风、回燃、水冷却、结构失效。
- **解法矩阵测试**：每个障碍 ≥3 动词，每个动词有可测结果。
- **确定性回放**：种子 + 输入 → 同一结果；复盘与测试共用。
- **可视化门禁**：房间切镜、烟层遮挡、关键交互、无页面异常。
- **音频门禁**：火/烟/水/脚步/无线电的电平与可解码。
- **性能预算**：JS/媒体包体、帧时间、场更新耗时；超预算即失败。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 系统太复杂，玩家看不懂 | 先做单房间；所有状态用烟色/热浪/声音/材质变化表达；调试可视化 |
| 涌现结果不可控、难测试 | 固定步长 + 种子 + 输入回放；解法矩阵测试 |
| 浏览器性能 | 粗网格、5–10 Hz 场、分层烟、Worker、按需渲染 |
| 失去消防专业性 | 保留测温/回燃/低姿/通风/破拆作为核心动词，系统服务于这些判断 |
| 范围爆炸 | 严格按 Phase 0 验收后再扩建筑；每阶段有可玩的垂直切片 |
