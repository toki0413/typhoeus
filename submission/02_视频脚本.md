时长目标 **2 分 40 秒**（留 20 s 余量）。全程屏幕录制，无真人出镜，纯命令 + 产物展示。

## 录制清单（按顺序执行，每步都验证过）

```bash
# 1) 全链（先跑一次，视频里录第二次就快了）
python -m typhoeus.cli run

# 2) 情景落档（口径与历时必须声明；阈值只对 station/72h 成立）
python -m typhoeus.cli scenario 338.8 --basis station --hours 72

# 3) 决策可行域
python -m typhoeus.cli decide

# 4) 规划决策卡（浏览器打开）
start out/p32_规划决策卡.html
```

**打开的产物（按镜头顺序）**：
1. `out/p32_规划决策卡.html` ← 主角

## 第 0 段（新增，前 15 秒）：一条命令

录屏直接敲：

```
python -m typhoeus.cli demo --rain 320 --remaining 8
```

屏幕上立刻出现五段：你的输入 → 该启动什么 → 来不来得及 →
逐点积水 → 这条结论的边界。

**接着再敲一次，只改一个数**：`--rain 354 --remaining 3`。
屏幕上落档从 p80 跳到 p95，人员从 2 组变成 3 组，
「人员转移」从来得及变成来不及。**这是产品的关键性质：换输入就换答案。**

**不用注册、不用 API key、不用联网、约 1 秒出结果。**


### 第 0 段的最后 10 秒（最关键）

再敲一次，这次给**气象台的逐时曲线**：

```
python -m typhoeus.cli demo --rain-series-file storm.csv --remaining 6
```

屏幕上最后出现：

```
什么时候越阈：
  黄 ≥ 0.10 m   第 27.7 小时
  橙 ≥ 0.20 m   第 28.2 小时
  红 ≥ 0.50 m   第 29.5 小时
  峰值 0.981 m  第 33.7 小时

★ 距橙级还有 22.2 h，比你的提前量 6.0 h 更宽裕
```

**这句话是标量输入永远给不出的。** 同一总量、不同时间形状，
越阈时刻实测相差 26 小时——所以曲线不是精度问题，是能不能回答"什么时候"的问题。
