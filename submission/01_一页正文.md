# 一场雨之后，如何回答"该修哪里"

**——复合气候风险的可复算决策链条（宁波两台风实证：烟花 2021 · 梅花 2022）**

---

## 一、问题不在算得准不准

每场台风过后，城市要回答三个问题：

1. **哪些点必须动**（不是"哪里水最深"，而是"哪里一旦出事代价最大"）
2. **该用什么手段**（管网？调蓄？竖向？还是只需保住现有排水在运行）
3. **要做到什么程度**（雨再大多少会淹，或排水要加强多少倍才够）

一场台风从来不只带雨：风、雨、潮、涝四灾种在同一小时叠加
（2022 梅花登陆当天，宁波姜山镇"风力强劲、降雨量大、风暴潮叠加"，
16 个村社内涝、10 处下穿封道、转移 12,612 人——镇政府复盘报告原话）。
今天这个问题由设计院用 3–6 个月的专项模拟回答。**慢，且不给不确定性**。
而政府的方案编制是刚性的：国办《关于加强城市内涝治理的实施意见》（2021）要求
各城市到 2025 年形成"源头减排、管网排放、蓄排并举、超标应急"体系——
**每一座城市**都要把这句话落成"修哪里、修多少、值不值"。

**我们做的不是更快的模拟器，是这条决策链本身。**

## 二、方法：五步链条，每步可复算、可拒答

> **一条命令看全链：`python -m typhoeus.cli demo`**（读现有产物，约 1 秒；
> 加 `--run` 先跑全链，约 90 秒）。纯 CPU、零 API key、不需要注册。

```
给定雨量 → ① 分级 → ② 找病因 → ③ 定手段 → ④ 算门槛 → ⑤ 标可信度
```

| 步 | 做什么 | 依据 / 输出 |
|---|---|---|
| **① 分级** | 面雨量落档 → 响应等级、值守频次、人员装备、布点数 | 四档分位（p50/p80/p90/p95） |
| **② 找病因** | 关掉排水重跑 → 把涝因拆成"排水已承担 / 排水可再挖 / 雨本身不可消" | 四型分型：排水兜底 / 排水可挖 / 雨致 / 无汇流 |
| **③ 定手段** | 分型 → 手段（保运行 / 加管径 / 调蓄 / 补几何） | 与 GB 51222-2017 的 15 cm 判据对齐 |
| **④ 算门槛** | 反解：要达到目标需多大雨、多少排水能力 | 反问题（二分搜索） |
| **⑤ 标可信度** | 结论是否随情景翻转？模型在此有无信号？ | 翻转带 + 三态标记 |

**第②步是这个方法的核心。** 它把"哪里水最深"这个无法行动的问题，
换成了"这个点该用哪种手段"这个可以行动的问题。
**链条与城市无关**：换一场台风，只换输入，不换方法——2022 年梅花已验证
（见第四节）。

## 三、实证一：宁波"烟花"，全链 77 件产物（最深案例）

### 方法跑得通的部分

| 项 | 读数 |
|---|---|
| 分档→动作 | 338.8 mm → p90 → 三级响应 → 2 组 4 人 + 排涝车 1 台 → 12 处布点 |
| 加档的恶化 | p50→p95：峰值 **+17.7%**（0.493→0.580 m），**橙格 +73.1%（1054→1825）**——恶化在面积不在深度 |
| 降雨可信度 | 三个独立来源一致：ERA5 259.1 / CHIRPS 234.3 / 批量 202.5 mm |
| 面积级水面识别 | SAR U-Net 留出集 **IoU 0.595**（0.514–0.684）vs Otsu 0.184，**7/7 全胜** |
| 常水体 vs 新增积水 | 337.38 公顷 vs **4.34 公顷**（新增仅占 1.3%） |
| 病因定位 | FP006 建兴路下立交：排水能力降到全域均值 **10%**，水深 0.001 → **0.467 m**（实测 0.50，差 7%） |
| 反解门槛 | 达 15 cm 需 **340 mm**（本次 1.31 倍）；压到 50 cm 只需现有排水能力的 **12%** |
| 决策可行域 | 信息→行动空白 **11.5–17.5 h**：停梯/封道/泵车可执行，**人员转移差 0.5 h** |

### 方法明确拒答的部分（这才是可交付的关键）

| 不能用 | 证据 | 我们的处理 |
|---|---|---|
| 原始模型水深 | 17 点命中 0%，MAE 0.359 m，12 点恒为 0 | **不给原始值**；给**校正读数 +0.359±0.103 m**（留一法 MAE 0.0909），仅作通报口径对齐，非物理真值 |
| 点位排序 | 宽松阈值 ρ=0.72 看似显著，≥1 mm 时 n=6、p=0.18 | 判定"秩技能未确立"，**不给排序建议** |
| 真实演进时序 | 起水同步（提前量 p25–p75 差 1.3 h） | 只给"会不会有水"，不给"几点到" |
| 域外 | 28 个涝点中 11 个域外；10 条断供中 8 条域外 | **单列为域覆盖问题，不掩盖** |

**28 个点位里，只有 4 个能承载规划建议——这张卡上每个点都带可信度标记。**

### 为什么"敢拒答"是产品能力而不是缺陷

政府做方案编制，最怕的不是"数字不精确"，是**"不知道哪个数字能信"**。
一条能说清"此处可用、此处不可用、不可用的地方该怎么办"的链条，
比一条声称处处精确的链条，在采购与审批环节更有价值。

## 三之二、跨事件证据（这是主证据，不是单场案例）

### 18 场 / 36 年（1990–2025）

| 项 | 值 |
|---|---|
| 分级分布 | 严重 3 / 较重 4 / 中等 3 / 轻微 1 / 无感 2 |
| 面雨量跨度 | 2.2 – 291.6 mm |
| **跨事件 Spearman ρ** | **0.9945**（n=13） |
| 严格单调违背 | 1 处，降幅 **3e-4**（量化误差量级） |
| 每场水量守恒 | 残差 ≤ **6.40%**（门槛 8，容差 20%） |
| **出现过红格的场次** | **8 / 16**（红格最多 TODD **86.0 ha**、FUNG-WONG 59.5 ha） |

**烟花只是第 2 大**（Q=0.485），最大是 1998 TODD（0.607）。
用单场定义产品，会同时高估与低估其他场次。

### 气候叙事：风险相关的 ENSO 相位在拉尼娜侧

历史尾部三场 **0 场**处于厄尔尼诺；最大场 1998 TODD（291.6 mm）在**拉尼娜**年（ONI −0.83）。
气候学机制一致：类拉尼娜升温模态使台风生成位置西移、华东登陆增加
（Shan et al., *J. Climate*, 2021）。

**因此我们的气候叙事不建立在"厄尔尼诺更频发"上，而建立在已观测到的类拉尼娜趋势上**——
后者是当代已发生的事实，比未来情景更可辩护。

## 四、实证二：宁波"梅花"，第二场全链验证（可迁移性）

同一驱动器、同一内核、同一判定规则，换事件参数后五步链端到端跑通，
双口径（参数化 / ERA5 再分析）并列。完整报告：`docs/muifa-deep-dive.md`。

| 对比列 | 烟花 IN-FA 2021 | 梅花 MUIFA 2022 |
|---|---|---|
| 登陆 | 07-25 舟山普陀 | 09-14 20:30 舟山普陀 |
| 72h 面雨量（ERA5 口径） | 259.1 mm | **171.5 mm**（通报 24h 全市均 179.7 mm，同量级） |
| 全域峰值水深 | 主链口径 | **0.998 m** |
| 功能损失 Q | 0.4851 | **0.3409**（参数化口径与 18 场批量记录逐位一致） |
| 五步链产物 | p13–p32 共 31 件 | m17/m20/m21-22/m32 同构 4 件 |

三条如实记录：

1. **参数化雨场在梅花上偏干 4 倍**（40.7 vs 171.5 mm）——与烟花场上
   同方向的系统性偏差；可主张读数取 ERA5 口径。
2. **强度—损失曲线不跨口径使用**：梅花在两个口径下的落点偏离分别为
   1.96×与 0.46×（烟花参数化口径自身偏离也是 0.46×）——偏离来自口径
   混合而非场次异常。
3. **精度迁移不主张**：梅花域内仅 1 个可定位通报点（老外滩），且为
   **潮位倒灌**——雨-涝内核在此无信号属预期，恰恰标出了复合风险里
   "潮"这一格的位置。

**判定：链条可迁移 PASS；精度迁移不主张。**

## 五、复合气候风险全谱：现在能做什么，不能做什么

一场台风 = 风、雨、潮、涝叠加。四层现状，每格带可判定口径：

| 灾种层 | 现状 | 证据 / 缺什么 |
|---|---|---|
| **雨→涝** | ✅ **PASS**（本链条主战场） | 烟花 32 件产物 + 18 场历史批量标定 + 梅花同构验证；识别/评估/转译三层全通 |
| **潮→涝（顶托）** | 🟡 **BLOCKED**（机制已诊断） | 涝点高出河网中位 5.63 m，5/17 点可能受顶托；老外滩倒灌为直接观测。缺：宁波"河网水位"应用的逐时数据接口（应用已上线，数据未公开） |
| **风** | ⛔ **未接入**（明示，不假装） | 内核不含风荷载与风毁机制；不输出任何风灾读数 |
| **生命线断供** | ✅ **PASS**（影响评估层） | 10 条真实断供通报检验预判能力（p13）；梅花场新增 6 条通报入库 |

**赛道三层任务链 ↔ 产物映射**：复合风险识别（μ_t 台风测度 / 四档分级）→
影响评估（Q 功能损失 / 归因分型 / 恢复次序 +27.8% / 生命线预判）→
应急信息转译（涝点卡 28 张 / 决策卡 / 可信度四标签）。
三条学科腿（气象科学 / 城市建设 / 打破信息不对称）各供一层，
误差经转译层的控制项才允许出口。

## 六、市场：三类玩家，缺同一个位置

| 谁 | 卖什么 | 缺什么 |
|---|---|---|
| 水科院 / 设计院 | 设计级模拟 | 3–6 个月、不给不确定性 |
| 平台商（城市智能体） | 监测联网 | 有观测，**无外推** |
| 国际风险图商 | 全球粗粒度风险 | 中国本地化不足 |
| 学术易感性制图（RF/CatBoost 类，含 npj 级期刊） | 静态风险分区 | 是**历史模式外推**，答不了"雨再加 30% 会怎样"；随机切分验证、无门槛无拒答 |

**没有人卖"把一场雨翻译成该修哪里"的快速可复算沙盘。**
相邻战场也在佐证：海绵城市行业为"好用不好看 vs 好看不好用"缠斗
（设施设错点、指标空转、运维缺位——`docs/sponge-city-fit.md`），
缺的都是同一个东西——**哪个设施真有效的判据**。

### 我们的位置

- **不做**平台（不竞争政府的监测网）
- **不做**设计院（不替代施工图）
- **做**两者之间的**可复算决策层**：嵌在既有监测之上做外推，产出可进方案的决策卡

### 第一个切口：宁波 149 点监测网

宁波市大数据局 + 市水利局在 2021 烟花期间已上线"台风积水地图"：
**149 个内涝监测点、红橙黄三档（0.5/0.2/0.1 m）、物联网实时、带水深变化曲线**。

- 官方有**现在**（观测），我们有**未来**（情景外推）——互补，不竞争
- 实测（留一法）：用观测插值替代模型模板，MAE 从 **0.359 → 0.097 m**
- 诚实限定：在 17 点稀疏度下，这只校正**水平**，改不了**空间格局**；149 点后可能质变

**这条切口的价值**：它是唯一能同时修"点位水深"与"域覆盖"两个死结的数据源。

## 七、能力边界（随产品交付，一次说清）

**这套产品回答"该做什么、先做什么"，不回答"某个点会淹多深"。**

1. **分两层说点位水深。**
   **原始模型水深不给**——17 点命中 0%、MAE 0.359 m、12 点恒为 0。
   **校正读数给**——加性校正在 17 点上留一验证，MAE 0.3593 → 0.0909（−75%），
   带 ±0.103 m 带宽。但它只用于**与通报口径对齐**，不是物理真值；
   且校正量在观测 0.20–0.50 m 区间标定，观测越浅越过度校正。
   **排序不给**——秩技能未建立。分型与门槛来自模型自对照，不是实测归因。
2. **不给真实的退水时间与韧性指标。** 模型能算出功能曲线，但固定 72 h 窗口
   会奖励短事件、退水时刻又受降雨脉冲干扰，故这两项**不对外引用**。
3. **强对流不在覆盖内**（缺雷达 QPE，峰值低估 10.5 倍）；
   **风驱雨未建模**；顶托是常数或合成时程，非实测潮位过程。
4. **投资排序带指标口径**：排水在峰值与点位两指标上都第一（×2.81 / ×5.46），
   可放心用；其余轴的排序随指标变化，引用时必须连同指标一起引。
5. **27 条门槛里 7 条 BLOCKED**，逐条写明缺哪个外部读数——
   它们全部指向同一件事：**管网台账与雷达 QPE**。
   未取得任何合作意向，149 点接入为"拟对接"，非"已合作"。

| 顺序 | 动作 | 已验证收益 | 需要什么 |
