# 一场雨之后，如何回答"该修哪里"

**——内涝治理的可复算决策链条（宁波"烟花"实证）**

---

## 一、问题不在算得准不准

每场内涝之后，城市要回答三个问题：

1. **哪些点必须动**（不是"哪里水最深"，而是"哪里一旦出事代价最大"）
2. **该用什么手段**（管网？调蓄？竖向？还是只需保住现有排水在运行）
3. **要做到什么程度**（雨再大多少会淹，或排水要加强多少倍才够）

今天这个问题由设计院用 3–6 个月的专项模拟回答。**慢，且不给不确定性**。
而政府的方案编制是刚性的：国办《关于加强城市内涝治理的实施意见》（2021）要求
各城市到 2025 年形成"源头减排、管网排放、蓄排并举、超标应急"体系——
每一句话都要落到"修哪里、修多少、值不值"。

**我们做的不是更快的模拟器，是这条决策链本身。**

---

## 二、方法：五步链条，每步可复算、可拒答

```
给定雨量 → ① 分级 → ② 找病因 → ③ 定手段 → ④ 算门槛 → ⑤ 标可信度
```

| 步 | 做什么 | 依据 / 输出 |
|---|---|---|
| **① 分级** | 面雨量落档 → 响应等级、值守频次、人员装备、布点数 | 四档分位（p50/p80/p90/p95） |
| **② 找病因** | 关掉排水重跑 → 把涝因拆成"排水已承担 / 排水可再挖 / 雨本身不可消" | 四型分型：排水兜底 / 排水可挖 / 雨致 / 无汇流 |
| **③ 定手段** | 分型 → 手段（保运行 / 加管径 / 调蓄 / 补几何） | 与 GB 51222-2017 的 15 cm 判据对齐 |
| **④ 算门槛** | 反解：要达到目标需多大雨、多少排水能力 | 反问题（二分搜索） |
| **⑤ 标可信度** | 结论是否随情景翻转？模型在此有无信号？ | 翻转带 + 三态标记 |

**第②步是这个方法的核心。** 它把"哪里水最深"这个无法行动的问题，
换成了"这个点该用哪种手段"这个可以行动的问题。

## 三、实证：宁波"烟花"，32 件产物

### 方法跑得通的部分

| 项 | 读数 |
|---|---|
| 分档→动作 | 338.8 mm → p90 → 三级响应 → 2 组 4 人 + 排涝车 1 台 → 12 处布点 |
| 加档的恶化 | p50→p95：峰值 +18%（0.493→0.580 m），**橙格 +72%（1058→1825）**——恶化在面积不在深度 |
| 降雨可信度 | 三个独立来源一致：ERA5 259.1 / CHIRPS 234.3 / 批量 202.5 mm |
| 面积级水面识别 | SAR U-Net 留出集 **IoU 0.595**（0.514–0.684）vs Otsu 0.184，**7/7 全胜** |
| 常水体 vs 新增积水 | 337.38 公顷 vs **4.34 公顷**（新增仅占 1.3%） |
| 病因定位 | FP006 建兴路下立交：排水能力降到全域均值 **10%**，水深 0.001 → **0.467 m**（实测 0.50，差 7%） |
| 反解门槛 | 达 15 cm 需 **340 mm**（本次 1.31 倍）；压到 50 cm 只需现有排水能力的 **12%** |
| 决策可行域 | 信息→行动空白 **11.5–17.5 h**：停梯/封道/泵车可执行，**人员转移差 0.5 h** |

### 方法明确拒答的部分（这才是可交付的关键）

| 不能用 | 证据 | 我们的处理 |
|---|---|---|
| 点位水深绝对值 | 17 点命中 0%，MAE 0.36 m，12 点恒为 0 | **明确不做逐点水深承诺** |
| 点位排序 | 宽松阈值 ρ=0.72 看似显著，≥1 mm 时 n=6、p=0.18 | 判定"秩技能未确立"，**不给排序建议** |
| 真实演进时序 | 起水同步（提前量 p25–p75 差 1.3 h） | 只给"会不会有水"，不给"几点到" |
| 域外 | 28 个涝点中 11 个域外；10 条断供中 8 条域外 | **单列为域覆盖问题，不掩盖** |

**28 个点位里，只有 4 个能承载规划建议——这张卡上每个点都带可信度标记。**

### 为什么"敢拒答"是产品能力而不是缺陷

政府做方案编制，最怕的不是"数字不精确"，是**"不知道哪个数字能信"**。
一条能说清"此处可用、此处不可用、不可用的地方该怎么办"的链条，
比一条声称处处精确的链条，在采购与审批环节更有价值。

## 四、市场：三类玩家，缺同一个位置

| 谁 | 卖什么 | 缺什么 |
|---|---|---|
| 水科院 / 设计院 | 设计级模拟 | 3–6 个月、不给不确定性 |
| 平台商（城市智能体） | 监测联网 | 有观测，**无外推** |
| 国际风险图商 | 全球粗粒度风险 | 中国本地化不足 |

**没有人卖"把一场雨翻译成该修哪里"的快速可复算沙盘。**

### 我们的位置

- **不做**平台（不竞争政府的监测网）
- **不做**设计院（不替代施工图）
- **做**两者之间的**可复算决策层**：嵌在既有监测之上做外推，产出可进方案的决策卡

### 第一个切口：宁波 149 点监测网

宁波市大数据局 + 市水利局在 2021 烟花期间已上线"台风积水地图"：
**149 个内涝监测点、红橙黄三档（0.5/0.2/0.1 m）、物联网实时、带水深变化曲线**。

- 官方有**现在**（观测），我们有**未来**（情景外推）——互补，不竞争
- 实测（留一法）：用观测插值替代模型模板，MAE 从 **0.359 → 0.097 m**
- 诚实限定：在 17 点稀疏度下，这只校正**水平**，改不了**空间格局**；149 点后可能质变

**这条切口的价值**：它是唯一能同时修"点位水深"与"域覆盖"两个死结的数据源。

## 五、边界（随产品交付，一次说清）

1. **点位水深不可用**是当前能力的硬边界，不是待修 bug——根因是管网台账缺失与 DSM 分辨率。
2. 所有分型来自**模型自对照**，不是实测归因。
3. 观测水深为公开通报口径（5 处下立交统一 0.50 m，可能被取整）。
4. **未取得任何合作意向**，149 点接入为"拟对接"，非"已合作"。
5. 27 条门槛的当前状态：**15 PASS / 5 FAIL / 7 BLOCKED**，全部逐条写明缺哪个外部读数。
